# Feishu Bitable task connector

This package projects an evoLoop task into one configured Feishu Base table and reads possible human edits. PostgreSQL remains authoritative. The coordinator must persist the outbox intent, recheck permission and visibility before calling `project`, and persist each returned binding or unknown outcome. An incoming candidate is never a TaskStore mutation; core must verify the actor, current local version, allowed fields, and status transition.

Configuration requires a custom app ID and secret, Base app token, table ID, and five distinct Bitable columns: stable evoLoop entity ID, local version, operation ID, title, and status. Pass the secret from the runtime secret store. The connector uses the current OAuth tenant token endpoint, caches by `expires_in`, and never includes token values or response bodies in errors. `apiBaseUrl`, `authUrl`, and `fetchImpl` exist for isolated tests; production should use the defaults.

On create, the connector scans the configured table for the stable entity key, then writes and reads back. A lost response returns `unknown`; the coordinator must persist that state and next call with `deliveryState: "unknown"`, which only reconciles. Scan is bounded by `maxScanPages` (default 20 pages of 100 records); hitting the bound stays unknown. Existing bindings use their record ID, and a missing record becomes a conflict observation rather than deleting the local task or silently recreating the projection. Updates compare the last confirmed marker and modified time before writing, but Feishu does not provide an atomic compare-and-swap through this API; concurrent edits during that interval remain a conflict risk. Restrict editable columns or pause writeback if this risk is unacceptable.

Run `npm run build --workspace @evoloop/connector-feishu` and `npm run test --workspace @evoloop/connector-feishu`. HTTP fixture tests cover the request shapes and failure paths. No tenant credentials, app permissions, real Base schema, webhook actor identity, or live account behavior have been verified. Enable production writes only after a controlled tenant and column mapping are checked with readback and a removable test record.
