# 评价方法：这套接入流程是否有效

本页写给改动或验收 `evoloop-onboarding` 的人。方法沿用 [development-workflow 的评价方法](../../development-workflow/references/evaluation.md)：让没有会话历史的 Agent 实际执行，再按事先定好的判据看结果。**执行者不读本页**：试跑时给它的检出里不放本页，判据和注入的故障只由评价者掌握。

## 要回答的两个问题

1. **向前：** 一个没看过任何接入对话的 Agent，只凭本 skill 和它链接的文档，能不能把一个真实的小项目从零接入，直到第一个 Task 被独立验收并关闭？
2. **读回：** 接入后漏配一项授权，按本 skill 的终态核对，能不能发现并指出是哪一项？

## 试跑设置

| 项 | 要求 |
| --- | --- |
| 执行者 | 新起的 Agent，不继承会话历史（`fork` 以外的子 Agent，或新的 Session）；记录实际模型 |
| 候选版本 | 固定一个提交，从它建一个单独的检出；检出里只有 SKILL.md 及执行要用的 references，不含本页 |
| 实例 | **自建实例**：独立的 PostgreSQL 测试实例（`scripts/ops/test-pg.mjs`）、独立端口、仓库外的私有目录。预先放一个“既有项目”和需求 Session 的身份，模拟今天“已有常驻实例、加一个新项目”的情形；给一个启停脚本代替主机的服务管理器 |
| 运行时 | 真实模型运行时（与正式实例同类型的登录与可执行文件），选最省的模型；不碰正式实例的数据库、端口、私有目录 |
| 样本项目 | 一个真实的小仓库（本机裸仓库，有测试、有“下一步想做”的列表），没有网络远端 |
| 身份边界 | 预置一个“使用者本人”身份，告诉执行者不得用它的令牌；执行者用需求 Session 的身份 |
| 授权 | 在说明里写明使用者已授权的决定类操作（接受 Role、新建 Session、选模型）和编制上限 |
| 问人 | 执行者联系不到人：本来要问的写进 `questions.md` 并按默认继续 |
| 记录 | 执行者按步骤写 `log.md`（UTC 起止、读回、卡点）；评价者另存说明原文与判据 |

## 两段

**A. 接入。** 执行者从“已有实例、新项目还没接入”开始，做到终态清单 E1—E10。评价者不插手，只在执行者越界时中止。

**B. 漏配注入。** A 结束后，评价者在 integrations 里删掉一条授权（默认删“验收 Session → Leader”这一方向的消息授权：只配一个方向是最常见的漏配，`session prepare` 不检查它），不告诉任何人删了什么。再起一个新的 Agent，只给它本 skill、实例现场和“请按终态清单核对这个已接入项目”的任务。

## 记录哪些指标

| 指标 | 怎样记 |
| --- | --- |
| 终态逐项 | E1—E10 各为通过 / 未通过 / 未到达，附读回证据；评价者自己用 CLI 复核，不只看执行者的报告 |
| 问人次数 | `questions.md` 的条数；每条判为“skill 本该回答”或“确实要使用者决定” |
| 卡点 | 每个卡点：步骤、现象、耗时、怎样解决、skill 有没有写到、属于 skill 问题还是产品缺口 |
| 用时 | 总时长与各步时长（以 `log.md` 和对象的创建时间为准） |
| 读回发现 | B 段：是否发现缺项、是否指出了具体配置项和方向、用了哪条读回 |
| 越界 | 碰正式实例、用使用者令牌、令牌进日志、全局安装：出现一次即本次试跑无效 |

## 什么结果算 skill 有效

同时满足：

- A 段 E1—E9 全部通过，E10 留下了接入记录；
- “skill 本该回答”的问题不超过 2 个；
- 没有越界；
- 每个卡点要么靠 skill 或它链接的文档解决，要么被正确识别为产品缺口并按 skill 的绕行处理；
- B 段发现了注入的缺项，并指出了配置项与方向。

## 什么结果要改 skill

出现任一条就改，改完用同样设置再跑一次：

- 某个终态因为 skill 没写、写错或顺序不对而未达成；
- 执行者做了与 skill 相反的动作，或在 skill 已写的地方仍要问人；
- 某个卡点 skill 没写到、且耗时超过 15 分钟；
- B 段没发现缺项，或发现了但指错了位置。

服务缺陷、缺少的产品能力（例如第一个 Role 的引导）、模型额度等不算 skill 失败：记成产品缺口，另建 Task；skill 只需写清现象与当前绕行。

## 局限

- 执行者与作者可能是同一模型系列，共享系统指令与先验；一次试跑是小样本，只说明这一次的设置下能走通。
- 自建实例的“既有项目”与正式实例的规模、历史不同；发布切换、额度用完、多机器等情形不在本方法覆盖范围内，按需另设情境。
- 试跑用真实模型，费用与时长随模型变化；报告里写明所用模型。
