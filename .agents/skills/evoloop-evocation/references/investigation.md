# 从多Session取证到Evo判断

用于正式周期复盘或需要跨Session解释的问题。Evo维护一份整体认识，取证助手提供互补材料，独立QA检查最终报告；三者不是可互换的完成证明。

## 先固定共同依据

记录用户当前目标、上轮固定报告与改进、观察起止/时区、各来源续读位置及本轮要支持的决定。默认从上轮**观察截止点**开始，提交时间另记；首轮显式选起点。会话仍在运行时冻结切点，后续现场读回注明时间差。跨阶段按实际接手/处理事件分界，不能仅凭Session创建、消息创建或重启叙述划界。

覆盖观察期内相关的活跃、已结束、暂停、归档或换承载工作；从Leader进入重要需求与交接，必要时回查旧依据。对重要需求保留“原意—Task/明确未建—结果—差距/后续”的对应，不另造一套业务状态表。用户后来改变方向、普通追问和真正取消分别判断，不因插话就默认原任务取消。

## 怎样使用 session-forensics-v4-2

先发现并读取当前环境可用的 `session-forensics-v4-2/SKILL.md`，核其脚本帮助；不硬编码作者机器路径、不自动安装全局副本。用户明确指定但不可用时说明工具缺口；仍可读取已授权原件，不能声称已完成该Skill检查。记忆检索只定位历史决定，原始会话与固定成果才支撑历史判断。

| 能力 | 在Evo中解决的问题 | 使用边界 |
| --- | --- | --- |
| `session_locate.py`、`liveness.py` | 找全同一工作不同文件/承载，区分活跃、旧副本和冻结范围 | 本地trace结尾不自动等于最新活动；现场状态不是过去状态 |
| `ledger.py`，带发起复盘的 `--origin` | 恢复人类请求、纠正、插话和授权，关联目标 | Agent摘要不冒充人类原意；续轮用已有地图增量续读 |
| `inventory.py`，指定仓库与切点 | 核当时已有Skill、文档和工作方法，查入口与实际使用 | 后来更新的规则不能倒填当时；读过不等于正确运用 |
| `drill.py`，每窗不超过50行 | 看决定性上下文、真实tool调用和回执 | 先定位再展开；不把整份raw JSONL塞进上下文 |
| `map.json` / `map.md`、更新与差异 | 串起目标、计划、过程、成果、偏差、下一步 | 主Evo持有总图；助手不同时改正本，不各造互相冲突的全案地图 |
| `brief.py`、独立challenge | 对关键推论找反证、核资源遗漏及最早偏差 | 事实抽取、推论挑战、整篇报告QA分别记录范围 |
| `map_check.py`、`render.py` | 检查请求归属、引用与可读取证产物 | 通过不证明解释充分、建议有效；Evo报告仍按用户问题自由编写 |

取证地图的 `answer.type` 按问题选择：进度用 `progress`，理解模型用 `distill`，原因用 `audit`，改进流程用 `process`。周期Evo复盘通常要解释原因并选择改变，不能因“分三期写”就只保留 `progress` 的检查。一个取证工具的输出结构不决定整份Evo报告的范围。

## 多个subagent按哪些维度工作

涉及多个角色和明显迭代的完整复盘，通常让两个或三个助手并行处理能独立调查的问题，主Evo同时维护总图与核心判断。按本轮证据选择或合并以下分工，不为凑齐维度开固定数量的Session。窄小追问直接处理；运行时无可用委派能力时按同样边界顺序调查并披露。

| 可委派的工作 | 输入与交付重点 |
| --- | --- |
| 意图、任务与Leader决定 | 用户原话、固定Task/Document、Leader关键窗口；核目标转写、未知阶段、优先级、依赖、遗漏及插话后的接续 |
| 执行、验收与角色方法 | 业务Session实际首包/通知、当时Skill、tool回执、Delivery及观察；核如何理解、采用了什么方法、返工与验收能证明什么 |
| 资源、Harness与效率 | 冲突双方Task/消费者、共享文件/环境、占用与释放、消息/Run阶段时间；核约束、可行替代、取舍者、等待责任和实际成本 |
| User独立亲用 | 普通用户目标、可用入口与访问范围；实际体验产品/对话/交接/成果，保留首次卡点，不提供内部根因或验收答案 |

User亲用可以复用适用的已有独立材料，也可以单独委派。它不是读trace的替代，更不是另一位助手复述作者的成功声明。研究Skill是否有效时，从后续真实任务的选择与动作取证；研究效率时，避免与其他助手重复计算同一段时间。

每个派工包写清：唯一问题、共同观察切点/版本、具体Session与窗口、允许查看的Task/原件、输出位置、禁止的副作用、已知权限边界。交回**判断或事实—来源位置/固定ID—支持程度—反证/替代解释—未覆盖项—值得补查的材料**。事实助手可用适合提取与核对的模型；承担完整观察建图和困难因果判断的Agent按forensics要求使用当前可用的强模型，支持时明确模型与effort，记录实际选择。主Evo保留核心裁决，无需另请同等角色重复盖章。

使用宿主现有subagent能力，复用适合的助手，文件所有权分开；不把临时取证者登记成产品常设Role，不递归扩团队，不为了复盘启动另一套团队Harness。现成事实索引可共享，争议结论由主Evo回原件核，不按票数裁定。已有完整模型留在主Evo，避免所有人各自读遍所有日志。

## 主Evo怎样合成，而非拼接

把各份材料放回“意图—输入—决定—动作—结果—使用”的同一条链。对每项重要发现区分：已观察事实、证据支持的解释、尚存竞争解释、建议与验证办法。优先补会改变结论的缺口，不为证明所有假设反复重跑业务。

特别核以下连接：

- Task各自成功但整体目标未实现；研究被按实施验收，或实现仍没有可操作判据。
- 作者与验收者理解了不同范围；通过之后没有明确的发布/复测责任。
- Leader决定了顺序，但执行者没有接手；资源释放后没人接续；跨阶段重复了同一失误。
- 行为符合已有规则但结果仍失败；规则未加载、难用、用错或本身错误分别处理。
- 新机制解决旧问题，却增加通知、读文档、审阅、部署或人工协调成本。

对资源冲突给出当时可行的取舍：串行、隔离环境/文件、拆交付、调整优先级或增加容量，核代价及受影响方。日常排程仍归Leader；Evo评价其决定并提出体系改进。

最终提出相称改变并交接，或有据保留现状。将关键结论交给每份报告的独立QA，不能把助手文件合并完或取证工具全绿当作复盘完成。
