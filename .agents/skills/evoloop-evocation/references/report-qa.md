# 每份完整复盘的独立QA

目标：让报告能支持有依据的取舍，包括**事实、思考深度和读者理解**。QA审的是固定报告；被复盘业务的验收记录、取证助手完成、引用检查和HTML能打开均不能替代它。

## 输入、独立性与责任

每份正式报告由未参与其撰写、没有自审自身交付冲突的独立审阅者检查。新聊天名称不自动构成独立；记录实际作者、审阅者及其参与范围。优先使用无作者对话历史的上下文；已参与部分取证时披露范围，不能独立确认自己是唯一来源的主张，应由另一审阅者核关键依据。主Evo对最终结论及修订负责。

给QA：用户问题和长期目标、报告固定文件hash或Document修订、观察边界、必要原件索引及访问方式、上轮改进、未覆盖范围。让它先阅读新稿并形成判断，不只给作者挑出的“请确认五项事实”。改版时在固定初判后提供旧稿固定版本，比较决定性细节是否误删。初判前不读教学案例、作者的改稿理由和对受审报告的既有评价；固定初判后可用于比较，记录哪些结论因此改变。若已接触同题评价就披露，不能称为未见答案的盲测。因果争议可提供双方解释，但不将作者偏好作为答案。跨多份报告可批量委派，仍逐份给出判断并核边界、重复和跨篇因果。

不为报告QA新建验收引擎或永久角色。通过当前允许的subagent/业务Session承担，审阅意见保存在本轮证据或Document内即可。不可用时保留待QA草稿并说明边界，不宣称已独立验收；不要求用户重复批准已授权的普通审阅。报告QA不成为日常业务和已授权修复的前置审批；普通追问、取证笔记及QA意见本身不递归新增整篇报告QA。

## QA怎样实际检查

| 检查 | 要做的事，不能仅勾选“有这一节” |
| --- | --- |
| 目标与覆盖 | 对照用户问题、上轮改进与任务组合，指出重要需求是否遗漏；抽查暂停/失败/已结束工作，核阶段拆分是否切掉后果 |
| 证据与推论 | 对中心主张回原始窗口、固定Task/成果与实际使用；核版本、身份、时间和证据范围，找支持不了结论的跳跃 |
| **思考深度** | 选择影响决策的发现，追问“这个事实为什么支持这个原因、还有什么解释、哪条反证会改变建议”；区分现象、机制、检测/恢复缺口和后果；找被忽略的成功或合理例外 |
| 方法与取舍 | 核任务阶段、角色方法、Skill实际采用、资源冲突及成本；容量结论要对照同职责实例、可并行任务与实际区间、限制及关闭后承接，不能由项目Session总数或单次故障代推。建议应对应断点，有较小替代、下一责任和可观察验证，不从故障直接推新Role/新Skill |
| 真实价值与改进回看 | QA所测场景是否代表用户目标；上轮建议是否改变实际工作，而非仅合入/部署；新负担及仍需用户介入的部分是否说明 |
| 图与阅读 | 从正文和图解释谁负责什么、工作如何接续、问题在哪、下一步为何值得做；区分目标图/现状/提议。普通入口核正文、关键图和证据链接；若无法亲测，明确该项未验 |
| 读者判断与旧稿保全 | 请审阅者在不参考作者预设答案时复述关键变化并选择有依据的下一步；核主文是否保留改变原因/取舍的反例、连续案例、数字含义与就近限定。改版时对照旧稿，指出误删、改写失真或仅移到读者无法找到之处的决定性细节 |

**深度看解释力，不看篇幅或措辞。** “卡在发布”要继续核为什么卡、谁能处理、有没有合理等待依据；“Skill已读”要核它是否影响实际动作；“根因未知”应指出缺证据如何影响建议及下一项有区分力的补查。证据只支持局部判断时，准确收窄比编造完整根因更好。不要强迫每个小事实都有长篇因果分析，也不要用统一深度分数奖励术语和字数。

QA应指出**具体段落/图节点—问题—原始依据或缺失证据—影响哪项决定—最小修订/补查**，并给每份报告一个明确结论：可作为该范围的完整复盘、需修改后复核，或仅支持限定的阶段材料。合理不同取舍不是缺陷；不要按作者预想答案判分。

## 修订、提交与下一轮

影响中心判断的无依据主张、重要目标遗漏、误导性因果或关键图文矛盾，应在宣称完整复盘完成前修正。未知有界且不改变主要结论的材料可以保留；方法建议尚未实跑不是报告必须等待未来效果的理由。

主Evo记录意见如何处理及理由；关键结论改变后，QA复核受影响部分，不为标点或已核未变内容重新跑全套。QA结论绑定受审版本；报告入库后核原件与受审文件一致并打开阅读，实质改写则原QA结论不自动延用。

读者可在报告中按需查看“如何核验”：谁审了哪个版本、查了什么、纠正了什么、还有什么未验。原始私密日志与凭据不进入公开Git或默认正文。QA记录不要求新增数据库字段或固定报告章节。报告通过说明它能支持本轮判断；改进是否有效仍由下一轮真实工作验证。
