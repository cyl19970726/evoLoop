# 站在读者角度选择表现形式

## 先定位理解阻力

读者可能遇到术语不清、关系太多、时间顺序混乱、看不出差别、不知道怎样行动，或无法判断证据。先识别阻力，再选表现形式；“这一段很复杂”不足以说明为什么要画图。

问四件事：读者已知道什么；现在必须注意哪些对象或变化；需要作出何种判断；最容易误解哪一步。只为当前理解任务展示必要信息，同时让相关细节可以继续阅读。

## 媒介判断与组合

| 思考任务／阻力 | 合适的主表达 | 为什么 | 何时不适合 |
| --- | --- | --- | --- |
| 概念、理由、推论、例外需要精确语言 | 有层次段落＋小例子 | 保留语义、条件和论证 | 将大量平行属性挤成长段落 |
| 多对象的组成、依赖或责任难以同时记住 | 关系图、架构图 | 让关系可同时查看 | 只有两条简单事实；边只能写“相关” |
| 需要跟踪动作、分支和回路 | 流程图 | 显示选择与后续结果 | 把数据对象、操作与机器混成同一加工阶梯 |
| 多方请求和返回的先后决定结果 | 时序图 | 显示参与者与消息顺序 | 只想解释静态职责或概念分类 |
| 关注合法状态、触发和恢复 | 状态图 | 区分发生了什么、还能去哪里 | 没有明确状态变化，只是功能列表 |
| 比较选择或核对同一组属性 | 表格 | 对齐维度，暴露缺口 | 各项不能按共同维度比较，或长文塞满单元格 |
| 看不见抽象机制怎样发生 | 连续案例／反例／前后对照 | 把概念、动作和条件绑定到具体对象 | 每段更换人物和条件，无法追踪变化 |
| 想完成已知任务 | 步骤＋可运行命令／实例 | 缩短行动距离，结果可核对 | 长篇背景埋没关键前提，或写未经核对的按钮 |
| 想认出真实页面位置或问题现象 | 带版本和标注的截图、必要短演示 | 给出实际视觉证据 | 用设计图证明已实现，或用截图代替机制解释 |
| 想检查数值分布、趋势和不确定性 | 来源明确的图表 | 显示数值关系与变化 | 样本或分母不明，用装饰图制造精确感 |

文字与图可以互补。例如先用一句话定义“正式版本”，再用状态图解释它怎样产生，最后以具体拒绝案例说明为什么候选不能直接成为正式版本。无需把相同信息完整复制三遍。

## 一张图怎样有多个维度

先明确对象身份和关系语义，再增加视角：

- 主结构表达最重要的关系；颜色、分组、线型或小标签编码必要的辅助维度，并有图例。
- 时间、证据状态、责任和内容类型是不同维度。同一颜色不能兼任“对象类型”和“已验证”。
- 同一组对象可在多图或交互视角中保持相同名称与身份；读者应知道当前视角关注什么。
- 需要大量图例、交叉线或例外时，分成有共同对象的两幅图。尊重用户一张总图的要求，仍保留必要条件；总图可导航，细节再展开。

星形、分层、左右或上下只是布局。远近不证明因果、支持或先后；箭头需要以动作或关系命名。来源支持哪个命题、操作改变哪个对象、模块调用谁，应直接说明。

## 设计读者在每一章的过程

可在草稿边写一条短线：

“他以为只是查询报告 → 在熟悉任务中遇到条件差异 → 看见旧认识与新问题如何组合 → 能解释新综合增加了什么 → 知道仍需哪些证据 → 能在下次任务中有条件使用。”

给每个转折选择表达：

- **定位问题：** 一段情境，出现具体困难与目标。
- **建立可指认对象：** 两条实际或明确假设的认识卡，保留依据与条件。
- **看懂关系：** 小图展示引用和推导方向；正文解释新增推理步骤。
- **判断边界：** 一个反例或条件变化，必要时用前后对照表。
- **进入行动：** 明确取舍、下一步与预期验证结果。

这是示例，不是固定模板。已熟悉的概念可以略述，任务入口可先给步骤并链接回解释。

## 图和正文的自解释要求

每幅图让人知道它回答什么、节点是什么、边是什么意思、边界怎样理解，以及目标和当前状态的适用范围。旁边选一个关键路径、反例或变化解释，不逐字念图。

重要限定放在对应主张或边上，而不只藏在页脚。仅有一个动作或事实时通常一句话即可。

## 验证表现形式

需要渲染交付时，查看实际输出：Mermaid 是否成功渲染、标签与关系是否清楚、图表与正文是否一致、链接是否到正确段落。窄屏优先合理重排；密集结构可提供有提示的局部滚动与可打开大图，不能缩到文字不可读。

解释不能只靠颜色、hover 或作者自知的缩写。正文保留主要结论和阅读路径，静态或辅助阅读环境也能取得核心含义。渲染通过支持技术可读性；理解程度需要复述、应用或判断来检验。
