# 按本轮目的接力

先读固定 Task 的目标、验收、约定的消费者；已有交付时再核当前 Delivery，然后分清本轮交什么。这里是责任判断；身份、版本、命令、未知恢复仍按[业务 Skill](../SKILL.md)和[CLI 指南](../../../../docs/development/agent-cli.md)执行。

| 责任 | 当前要作的决定与动作 | 留给下一位的证据 |
| --- | --- | --- |
| Leader | 核业务目标、本轮范围、关键未知与判据；选负责人、顺序、真实承接 Session 和独立验收者，处理冲突、未接手与失败。结果到达后决定采用、返工、停止或后续工作。 | 固定 Task、派单与排序、下一责任；不要把自己默认为实际使用者。 |
| 执行者 | 按正式派单读固定输入，在授权内选方法、做自检并本人提交当前成果；受阻时留原 Task 的具体问题。 | 可打开的固定成果、版本/hash、实际检查、限制与接收者；普通 Run 在有效期内签 `ordinary.submit`。 |
| 独立验收者 | 以 Task 指定的真实身份，从约定入口亲用当前 Delivery，先记录观察，再对照作者说明；不足则指出失败或未测及原因。 | 本人对当前交付的使用观察；不借作者 Run，也不以作者报告代替使用。 |
| 发布或采纳者 | 按 Task 约定和现行权限，核候选、独立结果、审阅/检查，再执行必要合并、发布或知识采纳；正式入口需复测时交指定验收者。 | 实际版本、环境、动作执行者和复测责任；未发生的步骤仍是待办。 |

**研究或探索**验其证据、反例和取舍是否足以支持下一决定；结论可为暂不实施。**方法或文档**验读者能否据此解释、行动或交接；若改了仓库，再按项目审阅合入。**工程改动**先核候选行为和必要检查，按约定合并、部署与正式入口复测。三者都要把技术完成、Delivery、实际使用、Task 关闭和后续采纳分开；研究完成不会自动发布，候选通过也不会自动成为正式效果。

当前队列按已保存的 Leader 安排与本 Task 的关闭条件释放；没有下一项的明确责任或条件时，由 Leader 决定继续、暂停或停止。通知、消息回复或 Run 终态只说明各自发生的事。发现独立新工作交 Leader 排序；当前判据失败留原 Task 返工，保留旧交付和观察。需求与 Evo 独立用 CLI 工作，本期不由任务引擎自动排程它们。
