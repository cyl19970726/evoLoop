# 写成果：让接收者能够作下一步决定

先回答本 Task 要支持的决定或行为：建议做什么、为什么、接收者现在可以做哪一步。结论可为维持现状、继续核查或停止，按证据表达；不要先铺运行日志和字段清单。随后给足能检验结论的关键事实、反例、未决点与下一责任。长轨迹、完整来源表和协议细节放可下钻的固定材料。

对每项关键判断分开写：**观察到的原件/动作**、**基于它的推断**、**尚未验证的范围**。标明实际执行者、Task/Run 固定输入、产物 Document 修订/hash 或 Git commit、技术检查与失败、人工介入。下载/hash 只证明取得字节；原生输出截断时不能声称模型看完。读者打开固定链接后应能核对所用版本。原始会话、凭据和私有材料留受控目录，不放公开 Git。

提交普通 Run 的 Document 报告时，先读回固定修订与 hash；产物引用的字段格式、单一位置和错误恢复按[普通 Run 本人提交](../../../../docs/development/agent-cli.md#普通-run-本人提交与终态封存)及实际 CLI schema 执行。

工程交付按实际阶段给 PR/head、检查、独立 review、merge、运行环境与消费者使用；未发生的步骤明确待办。讨论报告给来源、分歧、建议和下一次能区分判断的证据。Delivery 与使用分开：只写已真实发生的接收、阅读、采用或失败，不代消费者签观察。若有新问题，先看是否属于本 Task 的修复/返工；独立新工作才交 Lead 排序。

通过 evoLoop 承接的工程任务，在固定交付 Document 中给一份可重走的简短使用报告：**真实样本与普通入口 → 逐步操作 → 每步预期与实际结果 → 对应证据**。标明实际使用者、候选 PR/head、部署环境及实际版本、尚未发生的发布或复测、剩余限制和下一责任。失败修复保留原失败与同路径复测；前端改动附能说明差异的前后截图，并记录 CSS 视口宽高、缩放和截图像素宽高，正常窗口与短窗边界分开。旅程步骤引用[当前工作旅程](../../../../docs/frontend/journeys/current-work.md)，截图与公开材料按[文档维护](../../../../docs/development/documentation.md)维护，不把私有原图直接放入公开 Git。

开发者的自检报告供 Lead 在当前候选上独立使用；合并、发布、正式入口复测和关闭按[工程接力](../../../../docs/development/standards.md#共享主分支与审阅)继续，各步只补实际发生的证据。研究或讨论任务按其决定与阅读判据交付，无仓库变更不制造 PR，也不因报告已保存就宣称验收通过。

## 逐步使用报告示例

对应[HTML 完整阅读任务例子](writing.md#链接和例子)，报告可简写为下表。这里引用的是[当前工作旅程](../../../../docs/frontend/journeys/current-work.md#4-读固定成果并回到工作)记录的**旧在服观察**，不是修复后的通过记录；实际交付时换成当前 Task、PR/head、固定报告链接、修订/hash 与本轮复测证据。

| 样本、入口与操作 | 预期 | 已观察及证据 |
| --- | --- | --- |
| 从研究 Task 的成果入口点“查看固定成果”，打开固定 HTML 报告 | 进入指定修订，能在主阅读面连续读正文、图与末尾 | 固定修订 `9b2801d7` 可核；这次在服样本实量 CSS 视口 2880×1772、DPR 1、visual viewport scale 1、PNG 2880×1772 像素，iframe 仍约 1100px 宽、420px 高，完整阅读判据未通过。见[原截图](../../../../docs/assets/frontend-journey-20261101/04-html-reading-gap.png)及[来源](../../../../docs/assets/frontend-journey-20261101/source.json)。3342×2056 是参考图输出像素，不能推定用户 CSS 视口、DPR 或缩放；浏览器 UI 缩放未独立读出。 |
| 点“返回来源”，再返回任务列表 | 回到原 Task，保留查找上下文 | 该次观察恢复了搜索、状态和所选任务；见同一[旅程记录](../../../../docs/frontend/journeys/current-work.md#4-读固定成果并回到工作)。这不证明正文阅读问题已修。 |
| 在修复候选的同一路径复测，再由 Lead 独立使用 | 首段至末段、图文、返回路径均可达，前后截图条件可比较 | **待执行。** 补候选 PR/head、实际使用者、每步截图与窗口尺寸、失败或通过结果；失败回原 Task，保留上面的原失败。 |
| 候选通过后审阅、检查、合并、发布并从正式入口复测 | 正式版本满足同一判据，验收者据当前交付决定关闭 | **待执行。** 分别填独立审阅、当前 head 的 CI、merge commit、部署版本、正式入口复测和消费者使用记录；责任按工程接力条款，不以候选截图代替。 |

写真实报告时只保留本次做过的步骤与结果，未发生的步骤明确下一责任。截图或构建结果须对应所写的 PR/head 和环境；报告正文给可打开的固定 Document 链接、修订与 SHA-256，长日志下钻。
