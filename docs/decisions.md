# 决定与设计状态

2026-10-19。此页登记当前方向及待验证选择；引用来源是已公开抽象的项目要求和[历史来源说明](references/lineage.md)。原始会话不随公开仓库发布。编号用于其他文档引用，详细方案只在所属正文维护。

## 用户已确定的方向

| 编号 | 方向 | 对文档与实现的影响 |
| --- | --- | --- |
| DEC-001 | 职责从真实工作与效果证据中演进 | 不预置固定完整角色阵容；职责试行必须可回看、合并或撤回 |
| DEC-002 | 所有 session 都形成和使用认识，领域 session 可以负责修复 | 不设置唯一认知者或唯一执行瓶颈；委派仍有最终责任者 |
| DEC-003 | 专门的分工管理 session 判断新角色需求 | 综合日志以外的负荷、产物、使用、运行与未来目标证据 |
| DEC-004 | 专门认知 session 整合领域认识并推动下一步，初期同时承担 Wiki 综合维护 | 本轮补充明确其认知推进责任；全员仍能形成认识与处理本领域工作，是否进一步拆维护实例按证据决定 |
| DEC-005 | 第一阶段任务表使用飞书多维表格 | 先接现成平台，接口可替换，不另建同等可写任务权威 |
| DEC-006 | 认知正文在开发 repo 外，Markdown 可接受 | 正式文档在 Git；持续 Wiki、原始材料与运行数据独立存放 |
| DEC-007 | 正式文档可以由仓库源文件渲染 HTML | 只维护一份正文；可发布文档默认公开，未来使用项目子域名 |
| DEC-008 | 每阶段完成后实际使用产品或工作流，形成认识并影响下一阶段 | 实现完成、使用验收、认识变化分别有证据 |
| DEC-009 | 选择社区关注度较高的候选，分别验证 OpenViking 与 nashsu/llm_wiki | 两会话有限实验已完成；stars 和实验完成都不代表最终选型 |
| DEC-010 | evoLoop 建立独立公开 GitHub 仓库 | 发布正式文档和开发工具；历史归档及知识正文保留本地/外置空间 |
| DEC-011 | 所有可公开探索统一进入 `docs/research/` 并可在文档站阅读 | 原 validation 报告已归入 research；研究计划、观察与建议保留状态，原始运行材料不随报告公开 |
| DEC-012 | 以认知演进和协作执行两个维度思考产品，按四部分呈现架构 | 四部分为认知循环、动态多 session、Task 与状态机、LLM Wiki 与有效性评价；目标是有实际效果的 Agent loop，不预设四个固定岗位 |
| DEC-013 | 各领域从真实工作提出 dogfood issue 和新需求到统一任务表 | 区分来源、类型与接受状态；常规授权内修复可直接接受，需要独立判断的需求先分流再执行 |
| DEC-014 | 负责人的日常入口是与分工 session 讨论分工、与认知 session 讨论下一步 | 准备依据和选择，决定落入知识、任务和职责说明；常规工作不依赖人类传话 |
| DEC-015 | 支持一次性和周期性工作，并明确 Codex 接入与包边界 | 定时工作进入统一任务规则；协议、触发、恢复及实现结构须有明确说明与验证 |
| DEC-016 | 业务技术实现之前确认语言、核心技术、Wiki 集成/改造对象和包架构 | 先形成有依据的推荐与替代方案，明确包责任和版本能力，再推进业务代码；实验语言不自动成为应用选型 |
| DEC-017 | 从第一版使用 PostgreSQL 保存运行状态，减少以后更换数据库引擎的迁移成本 | 替代早先 SQLite 建议；飞书任务/日程与外置 Wiki 的权威不变。数据库版本、驱动、迁移、部署和恢复仍需落地验证 |

## 当前设计提议

| 编号 | 提议 | 验证后再决定的部分 |
| --- | --- | --- |
| PROP-001 | 用较薄的 harness 连接任务、知识与会话运行时 | 单活调度、身份映射、结果未知和交接恢复的真实能力 |
| PROP-002 | 首个真实试点使用 evoLoop 自身文档与协作任务 | 任务粒度、用户反馈、提醒负担和可比较基线 |
| PROP-003 | OpenViking 优先继续受限试点，知识发布先串行 | 固定新版并发保护、撤回来源维护、版本和原生恢复能否成立 |
| PROP-004 | 正式文档用轻量静态构建，HTML 不进 Git | 根据人类阅读和 Agent 定位效率持续调整入口，不复制业务专用大生成器 |
| PROP-005 | 首个运行时试点采用自管 Codex App Server stdio，桌面日常讨论经项目工具连接 | 固定版本生命周期、实际任务与恢复；桌面聊天自动控制及 UI 同步不在现有证明范围内 |
| PROP-006 | core、contracts 与平台适配分层，单活 daemon 装配；日程定义留在飞书 | 语言与部署选型、外置运行记录实现、真实表结构及时间/去重/重叠语义 |
| PROP-007 | 主应用推荐 TS/Node 24 LTS、npm workspaces、Fastify、Zod；运行存储引擎按 DEC-017 使用 PostgreSQL | [技术选型](architecture/technology-selection.md)待确认；依赖锁定、数据库驱动/迁移、协议迁移和恢复仍需首片验证 |
| PROP-008 | 推荐 OpenViking 独立服务作为 Wiki 基座，认知维护留在 evoLoop；必要时有限 fork | v0.5.1 是新候选而非已通过版本；核所有写入入口、来源撤回、修订/恢复及许可安排后再确定补丁 |

## 仍未选定或未实施

- [推荐技术基线](architecture/technology-selection.md)的正式采纳，包括主应用 TS/Node 与 OpenViking 服务边界；PostgreSQL 引擎方向已选定，版本/部署及恢复待验证。nashsu 保留体验参考，不作为本方案的第二个知识权威。
- OpenViking 固定版上线能力与有限 fork 的具体范围。新候选源码能力和 0.5.0 实测结论分别记录，正式服务尚未部署。
- 飞书实际租户、表结构、权限与并发/事件能力的现场验证。
- 首个运行时适配范围，尤其是唤醒、派发结果核对和重启后恢复。
- 公开文档站的域名、托管、自动发布和持续运维；公开 Git 仓库与部署文档站是两个状态。
- 项目许可证。公开源码可阅读不等于已选择某种开源许可证。

## 修订规则

新决定说明改变了哪一项、依据和影响；被替代的决定保留历史意义并标注替代关系。只改说明而没有同步产品、架构或执行方法，不算决定已经落地。文档维护方法见[维护规范](development/documentation.md)。

本次修订将 DEC-004 从“专门 Wiki session 维护综合认识”扩展为明确的认知推进责任，并新增 DEC-012；依据为用户对四部分与两个维度的确认。自动运行、具体状态转换与 evaluator 测试方案仍是待实施设计，不因文档修订而成为已验收能力。

后续修订新增 DEC-013—017，记录用户对 dogfood、日常讨论、定时能力、Codex/包边界及实现前选型的要求；PROP-005—008 保持设计建议状态。首次协议调查只验证初始化；之后[独立 PR #2](https://github.com/cyl19970726/evoLoop/pull/2)补上自管线程的受限夹具闭环和桌面宿主通知消费，未接通真实飞书任务、生产 Wiki 或定时流程。研究通过不等于语言选型已经确认。DEC-017 根据用户降低后续迁移成本的明确偏好，将运行存储从 SQLite 建议改为 PostgreSQL；不表示其他提案同时获批。
