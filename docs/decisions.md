## 仍未选定或未实施

- S1a 已按 DEC-028 采用[工程基线](architecture/technology-selection.md)并接通真实本机 API；尚未实施完整工作台、前端知识图谱及各适配器。nashsu 保留体验参考，不作为第二个知识权威。
- 远程工作台身份认证、常在线部署和真实多人使用；S1a 本机令牌模式与合成体验不证明这些能力。
- OpenViking 固定版上线能力与有限 fork 的具体范围。新候选源码能力和 0.5.0 实测结论分别记录，正式服务尚未部署。
- 飞书 connector 的实际租户、投影字段、权限、回写/并发和事件能力；云文档正文接入另行验证。
- 首个运行时适配范围，尤其是唤醒、派发结果核对和重启后恢复。
- 公开文档站的域名、托管、自动发布和持续运维；公开 Git 仓库与部署文档站是两个状态。
- 项目许可证。公开源码可阅读不等于已选择某种开源许可证。

## 修订规则

新决定说明改变了哪一项、依据和影响；被替代的决定保留历史意义并标注替代关系。只改说明而没有同步产品、架构或执行方法，不算决定已经落地。文档维护方法见[维护规范](development/documentation.md)。

本次修订将 DEC-004 从“专门 Wiki session 维护综合认识”扩展为明确的认知推进责任，并新增 DEC-012；依据为用户对四部分与两个维度的确认。自动运行、具体状态转换与 evaluator 测试方案仍是待实施设计，不因文档修订而成为已验收能力。

后续修订新增 DEC-013—018，记录用户对 dogfood、日常讨论、定时能力、Codex/包边界及实现前选型的要求；PROP-005—008 保持设计建议状态。首次协议调查只验证初始化；之后[独立 PR #2](https://github.com/cyl19970726/evoLoop/pull/2)补上自管线程的受限夹具闭环和桌面宿主通知消费，未接通真实飞书任务、生产 Wiki 或定时流程。研究通过不等于语言选型已经确认。DEC-017 根据用户降低后续迁移成本的明确偏好，将运行存储从 SQLite 建议改为 PostgreSQL；不表示其他提案同时获批。

用户随后确认 evoLoop 保存主数据、飞书作为 connector。DEC-018 明确替代 DEC-005 的任务权威部分：PostgreSQL 从运行记录扩展到项目对象。此前把文档表解释为“原生需求与 Git 引用模式的统一目录”是设计误解，用户通过 DEC-023 明确纠正：Document Table 只有过程文档，直接关联 Task Table；repo `docs/` 独立维护。DEC-022 的内容沉淀关系仍成立，不代表两者属于同一表。Task、文档采纳、运行、同步与实际效果保持各自状态，正文和关系的具体合同仍需实现验证。历史研究按当时前提保留，不据此恢复已经取代的权威安排。

DEC-027 依据用户本轮“暂时用 OpenViking、以后可能自己实现知识库、保留类似 nashsu 的图谱前端”的要求。新增可替换合同与迁移验收，明确后端方向已选但生产能力未验；历史研究仍保留当时的候选状态。

DEC-028 来自用户要求“全面 review 所有设计，没有问题就开始实现”，并要求多角度审阅。工程实现中仍发现并修正了具体合同与恢复缺口，见[设计审阅与首片实测](research/design-review-20261020.md)。它授权可逆的实现选择，不把所有候选技术、生产发布或完整产品验收视为已完成。
