# 知识底座验证摘要

2026-10-19 · 第一轮有限实测。两个独立验证会话分别运行 OpenViking 与 nashsu/llm_wiki，使用同一组 8 条中文需求重建材料，按批次加入旧建议、用户纠正、交接分歧和职责判断样例。这些是合成样本，不是完整历史会话审计。

本文是可发布的工程记录摘要；完整操作响应、截图、模型日志和产物在本地独立实验空间。这里报告的成功、失败均受版本与样本范围限制，未完成生产接入或最终选型。

要了解两套产品在这些实验之外的完整主要功能面与工作链，阅读[功能与流程对比](wiki-feature-comparison.md)。该页把原生功能、模型流程与实际验证分开，并提供 Mermaid 流程图。进一步的因果分析和测试方案见[机制与有效性验证](wiki-effectiveness.md)，其中新增测试均未执行。

## 版本与比较条件

- OpenViking：实际运行 `0.5.0`，发行标签提交 `20f9c11362ad16193b0daa4a414e1095061af427`。
- nashsu/llm_wiki：官方 macOS arm64 `v0.6.12`，对应核查源码 `48fd970e206a02a6d2028d1dbfc41b7a0345bf0b`。
- 共同源材料 SHA-256：`5ff9caeeca6391a69b608c43fcf746f55fa6fdeff6f9e317080858e6c426cc3c`；评价规则不交给独立消费者。
- 正式独立消费与直接材料对照使用同类无历史上下文、GPT-6.1 Sol / medium。生成阶段经历不同模型配置、服务阻塞与恢复，并未形成完全同模型的端到端比较。
- 补查固定版发现，OpenViking 的 Codex adapter 未透传配置中的 temperature／max_tokens；这些不是已生效的生成端控制参数。详见[机制与比较条件](wiki-effectiveness.md)。
- 每条件的正式消费样本很少，不进行统计显著性或长期收益推断。维护者、官方 Skill、原生机制和额外适配分开记录。

## 观察结果

| 场景 | OpenViking 0.5.0 | nashsu/llm_wiki v0.6.12 |
| --- | --- | --- |
| 材料进入持久 Wiki | 资源和归档会话编译均实际运行 | 桌面摄入、独立 Markdown vault 实际运行 |
| 用户纠正旧认识 | 官方 Skill 编译后采用独立存储方向，旧提案标注被取代 | 新页采用纠正，但部分旧中心页仍保留过时状态 |
| 保留两个解释 | 保留各方依据与不确定性 | 分歧仍在，但一处来源摘要增加原文没有的日志位置描述 |
| 同基线并发修改 | 普通覆盖写入均成功返回，但较早更新丢失 | 显式覆盖存在同类丢更新；默认只创建能防误覆盖，不能代替条件更新 |
| 来源撤回 | 删除不会自动修订 Wiki；显式再次编译可更新 | 来源元信息和链接清理后，正文仍残留受撤回来源支撑的判断 |
| 新会话完成具体任务 | 能交付方案，但遗漏 Markdown 许可等部分约束 | 原生、外部维护和直接材料组均完成三个样本任务；消费者曾下钻来源纠正摘要 |
| 恢复 | 手动停服冷备恢复可用；原生打包恢复受权限阻塞未完成 | 手动 ZIP 备份恢复可用；原生归档 UI 未完成验证 |
| 阅读与纠错 | Agent 走通部分读取/编辑；来源链接有体验缺口 | Agent 走通部分页面阅读；存在失效关联链接，完整纠错未验证 |

MCP 写页能力已在 nashsu 实测存在，早期“未核到写页”的研究判断已被纠正。Review 状态变更也不能据此推断知识正文已经修订。

OpenViking 当天较新的主分支中可以看到条件写入/编译冲突处理的源码变化，**本轮未运行该版本**；不能将 0.5.0 的并发失败扩展为所有版本结论，也不能把源码变化视为已通过。

## 对产品设计的影响

1. **优先继续受限验证 OpenViking。** 先串行维护，固定新版补验并发、来源失效、页级修订和原生恢复；当前不是生产推荐结论。
2. **nashsu 可保留为阅读整理候选。** 当前不建议直接作为多个 session 自由写入的共享认知权威。
3. **搜索和正确回答不足以证明知识维护可靠。** 消费者可能依靠原始材料修正 Wiki；要分别检查知识本身、读取过程和最终产物。
4. **小样本未显示 Wiki 效率优势。** 两边直接读少量原始材料的对照更快且内容不差。长期跨阶段材料增长的收益仍待验证。
5. **人工与适配成本必须计入。** OpenViking 的实验性写入包装不能约束绕过它的写者；nashsu 外部维护适配丢失部分机器使用的来源字段。两者均未成为可直接复用的生产保证。

## 下一轮判据

固定版本和模型条件后，优先补齐当前缺口，再使用一段可持续、可比对的真实工作。每阶段需要实际消费知识完成任务，记录纠正采用、无依据判断、用户提醒、返工、读取与维护成本。来源撤回、重复请求、结果未知与备份恢复继续保留为关键反例。

真人使用满意度、长期业务收益、多机并发和生产权限均尚未验证。候选继续失败时应缩小接入范围或更换后端，不把已经投入的验证成本作为采用理由。
