## 本次规范与配置修订

- **PR与审阅：**贡献入口接入明确合入协议；审查结论对应 head/base，新差异只复核受影响内容；PR模板提示目标、验证边界和实际交付状态。
- **按风险验收：**在现有规范加入旧对象迁移后的继续使用、恢复身份和业务新意图区分、UI关键信息可见性与被测运行版本。普通文案修正不追加全套数据库或浏览器验收。
- **当前事实与分发：**AGENTS不再复制易漂移的迁移号；运行指南把当前检查结果引向路线图；`development-workflow` 工程 skill 纳入项目版本，区别于产品业务 skill。其他领域 skill 由其维护者分别审阅分发。
- **CI成本：**保留 PR 与 push main 的检查，去掉同一分支 push 与 PR 的重复触发；检查名称、内容与只读权限不变。必须状态的跳过/缺失行为仍需核对，不靠取消检查获得成功。
- **平台保护：**[配置模板](../assets/main-branch-protection.proposed.json)供审阅及单独启用，读取当前状态后再应用并回读。它没有自动部署或配置效果；实际检查名、来源和审批身份变化时应修订。

## 工程 skill 的实际评价

此前对本次纳入版本的 `development-workflow` 做过四项实际使用：三项初稿任务分别是修复合成 Python 项目的开发流程、为本地工具从零建立开发方式、核对 PR #3 的真实历史；表达改写后，第四项新任务实际修订合成交付流程。四名执行者均为 GPT-6 Sol、medium、`fork_turns=none`，不继承作者会话；正常任务输入与评价标准分开，权限和完成边界仍明确。作者复核产物，并重跑相应测试、打包、状态读取或文档检查；保留了初稿和表达修订的区别。

观察到执行者能修正不存在的命令与过宽扫描保证、保留他人笔记、拒绝以旧 head 的成功支持当前合并；从零建立规范时没有强加远端和 CD。表达改写后的执行者先辨认本地打包、响应超时与目标读回，再核查状态工具只是打印夹具，没有把它当真实部署证据。任务成功只支持这些范围；首轮成功未发现表达问题，用户反馈后才重写，因此不能把“能做完”当作“好理解”。

本次沿用已测主文与评价方法，工程控制附录新增审批身份和旧对象接续两条提示；这两条只完成差异审阅，未声称重新盲测。原始输入、私有历史与产物留在受控评价记录，不公开复制。合成任务没有实际远端部署；执行者仍共享系统规则和模型先验，夹具由作者设计，无随机对照、独立计时或长期样本，不能推出因果提效或跨项目普遍有效。

## 试行计划与完成判据

| 优先顺序 | 责任范围与产物 | 如何验收 | 成本与回看 |
| --- | --- | --- | --- |
| 先行：合入合同与平台门槛 | 仓库维护者配置 main；实现者与审阅者在 PR 留目标、检查、固定版本结论。具体规则见[合入与审阅](../development/standards.md#共享主分支与审阅) | 回读有效保护；在非破坏的测试 PR 核未满足检查时的限制，再核普通 PR 的 head、CI、审阅与 merge 回执 | 当前同 GitHub 身份不可自批；平台强制 PR/CI不等于强制独立审查。三项行为 PR 后看缺项和额外等待 |
| 相关模型变更：旧对象可接续 | 受影响领域实现者复用 PG迁移、core/API/CLI回归，按本次影响检查旧修订、Run、basis、journal与固定上下文 | 旧模式非空样本迁移后能继续工作或明确拒绝，旧历史不被回写；实际升级和恢复单独留证 | 只覆盖受影响组合，不为每次小修全量重验；合并重复断言而不删除有效约束 |
| 相关恢复变更：选对操作 | CLI/core及适配器维护者保持正式恢复语义和回归，细节以[CLI恢复](../development/agent-cli.md)为准 | 丢响应后原ID回读；允许核心命令才显式原意图重试，身份冲突拒绝；确认拒绝后新意图保留旧失败；外部动作单独对账 | 不再开发已经存在的 receipts retry；不通过删回执、换ID或代写成功走通试用 |
| 相关界面或服务交付 | 实现者给被测版本与环境；独立使用者从普通入口完成受影响路径 | 主动作、关键状态、固定原件、历史和返回实际可用；截图、API状态、代理与真人结果分别报告 | 有UI变化才补对应浏览器任务；可靠自动版本显示可替代手抄，但令牌不进报告 |
| 持续评价 | 现有责任者抽下一批真实工作，保留首轮失败与修正 | 记录适用版本、行为、产物、人工提示、返工与新增等待；符合/偏离/不适用/证据不足分开 | 建议三项试行作为案例，不作统计充分样本；保留有效、简化重复，无请求不建立周期监控 |

M1后的具体产品工作以最新路线图和已确认材料决定。本次不预造 M2 任务：若要声称知识改善后续行动，需核实际采用指定修订；若要声称比直接阅读更有收益，还需可比任务、效果和总成本对照。没有对照只报告案例，不给虚构百分比，也不把新增流程本身当成收益。

## 证据限制

部分子代理派工正文加密，未逐字重读全部原始工具材料；选取了成功、失败和纠正样本，不估计总体违规率。该轮 GitHub 正式 review 记录为空不否认本机代理审阅活动，两者也不能互换。真实 PG 的 CI不覆盖全部 Codex、Wiki、Feishu或浏览器行为；外置服务、真人长期体验和生产恢复均需对应证据。

本次没有复制原始审计记录作为第二任务权威，也没有把后来的颜色、总览顺序和人机分工要求追溯成早期违规。未来按新的实际使用、平台能力和成本修订本计划。
