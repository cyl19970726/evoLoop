# LLM Wiki 开源实现：独立知识系统候选（2026-10-19）

> **历史研究记录与修正。** 本文保留 2026-10-19 当时的只读判断；于 2026-10-19 整理为公开阅读版，未重新运行候选或核对上游最新版本。下文“nashsu MCP 未核到写页”是早期核查缺口，**不是当前能力结论**：后续固定 v0.6.12 源码与实际调用证实 `llm_wiki_write_page` 可写页；但样本中仍发生旧中心页未同步、显式覆盖丢更新及撤回来源后正文残留。见[首轮验证摘要](../references/validation-summary.md)和[功能与流程比较](../references/wiki-feature-comparison.md)。检索或写页接口存在，均不等于持续维护闭环已验证。文中 star 数是当日快照；`main` 外链仅代表当时访问位置。

## 判定口径与结论

这里的 LLM Wiki 指 Karpathy 提出的三层模式：保留原始来源，由 LLM 在摄入时增量编纂可读、互链的 Wiki，并持续查询、修订、检查。仅把文档切块检索的 RAG、一次性生成 Markdown 的工具、静态代码说明站均不算。**用户最新明确：Markdown 可以作为权威格式，认知不得写进 evoLoop 开发仓库；独立 vault/知识系统可接受。** 各 session 应经接口贡献有来源的认识，独立 Wiki 维护 session 管理冲突、过时、修订并把结论反馈给下一任务。下文较早核查中的“非 Markdown 权威”判断已按这一口径修正。

**当时的研究排序是优先验证 OpenViking，并保留腾讯、OpenWiki 与 nashsu 等高 star 候选；后续实测结论见上述公开报告。** 本文额外深核的 lucasastorian/llmwiki 具有可参考的程序接入能力；以下是能力比较，不代表优先部署它。用户补充偏好 star 较多的项目；lucas 约 1,697 stars，hosted Wiki 正文权威存 PostgreSQL，原文件/资产走 S3，并有 MCP、HTTP、来源引用图、stale 与 lint。**local 模式也是可接受的候选**：它用独立于开发仓库的文件夹作为 Wiki vault，SQLite 仅索引；无需为了满足当前要求强制用 hosted。hosted 编辑缺少客户端期望版本检查；语义冲突在两种模式都主要交给外部 Claude Routine/专门 agent，需做多 session 并发与治理验证。

**MDBrain 降为实现参考与可选验证。** 它在代码层确实实现了 MongoDB `wiki_pages`、来源/claim/evidence、scope、修订历史、冲突记录、维护流程、HTTP 与 MCP 入口、OKF 导出，功能形态很贴近目标；但目前仅约 2 stars，运行还依赖独立 Memongo 与 Atlas Search/MongoDB Atlas Local Preview。star 数不证明质量，主要影响此轮的生态与维护风险偏好。其冲突检测按空白分词、英文否定词判断，不能假定能处理中文 session 的语义矛盾；维护需操作员触发。MCP `wiki_apply` 未暴露调用方的 `expectedRevision`，但 HTTP PATCH 与引擎有条件修订保护，必须按实际接入路径测试，不能概括为系统完全没有并发保护。

star 较多的 LangChain `OpenWiki` 与 nashsu `llm_wiki` 也值得验证**独立 vault 用法**：前者的 personal 模式写入 `~/.openwiki/wiki`，后者可以把其项目路径设在开发仓库外；但 OpenWiki 的 host-driven MCP 页面生成目前偏代码仓库模式，nashsu MCP 目前主要提供读取/检索、Review 列表与来源重扫，未核到通用 Wiki 页面写入工具。Microsoft `llmwiki` 默认写工作区 `.wiki/`，与仓库分离需要另选 Wiki 根目录；Alexander Makarov 的 vault 可独立放置且擅长汇入多工具 session。不能再按 Markdown 格式排除它们，关键要验**外部 vault 位置、写入接口与多 session 维护闭环**。

**后续修正补记：** 上段的“未核到”仅描述当时的检索范围；固定 v0.6.12 后续已证实 MCP `llm_wiki_write_page`，并实际完成写读。它不消除写入并发、旧结论传播和来源撤回的风险；这些须按[验证摘要](../references/validation-summary.md)分别判断。

本次只读检查公开 README、源码、迁移、测试与许可证，**未安装、运行、部署任何候选，也未上传项目材料**。以下源码链接固定到核查时 commit，避免后续主分支变化影响证据。

## 1. MDBrain：代码已实现数据库 Wiki，不只是设计稿

**思想来源与存储。** [README](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/README.md) 明确提到 Karpathy 的增量编纂模式，并把 Wiki 定位为 MongoDB 文档集合。实际 [schema](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/src/wiki-schema.ts) 有 `wiki_pages` 与 `wiki_revisions` 集合、scope/scopeRef、claim 状态、evidence 种类、freshness、页面状态和冲突处置枚举；[WikiStore 运行入口](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/apps/api/src/wiki-store-runtime.ts) 初始化 MongoDB。故它不是仅在 spec 中画了数据库。

**接口与隔离。** [HTTP 路由](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/apps/api/src/routes/v1.ts) 有创建、更新、查询、搜索、lint、revision、OKF 接口；[MCP server](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/apps/mcp/src/server.ts#L673-L892) 提供 `mdbrain_wiki_search/get/apply/export_okf/import_okf/lint` 六个 Wiki 工具。scope 可为 session/user/agent/workspace/tenant/global，具体隔离由 scopeRef 标识；API 查询从认证上下文拿授权 scope，不能只依赖调用者传一个字符串。[API 代码](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/apps/api/src/routes/v1.ts#L2816-L2855) 是证据。接 evoLoop 时可把项目 ID 固定映射为 `workspace:scopeRef`，但必须实测不同身份/项目之间读写隔离。

**来源、冲突、修订。** [Wiki 结构](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/src/wiki-schema.ts#L64-L98) 支持 claim、evidence、provenance、freshness；[冲突实现](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/src/wiki-contradictions.ts#L58-L122) 要求词集合重叠至少 0.3 且恰好一边含否定词；其否定词是英文列表，重叠度按空白切词。因此**从源码推断不能指望它处理中文 session 的语义矛盾，本轮未实测**。[写入顺序](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/src/wiki-contradictions.ts#L396-L435) 是先检测冲突后去重，冲突留待解决。[冲突记录](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/src/wiki-contradictions.ts#L253-L277) 追加在页面而非丢弃，[解决函数](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/src/wiki-contradictions.ts#L337-L377) 可写 `newest_wins`、`authority_wins`、`human_escalation` 等状态与处理人/备注，但仅改冲突标签；没有证据显示它自动判别哪条 claim 有效、修订页面正文或向用户发起升级，且本轮在 HTTP/MCP Wiki 表面未查到该解决函数入口。evoLoop 的专门 Wiki session 仍须执行实质审阅/修订，必要时补接口。[revision 代码](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/src/wiki-revisions.ts#L25-L89) 保存页面完整快照与编辑者；但默认记录失败只警告、不阻止页面写入（有 `strict` 参数），需在实际调用链确认审计是否强制。

**增量维护与并发边界。** [maintenance 代码](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/src/wiki-maintenance.ts#L161-L204) 根据来源内容 hash 发现变化并调用 LLM 更新对应页；[README](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/README.md#L313-L321) 明确两类维护由 `bun run wiki:maintenance` **操作员触发**，不是常驻自治服务。[HTTP PATCH](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/apps/api/src/routes/v1.ts#L2550-L2599) 接受可选 `expectedRevision`，不一致返回 409；[MCP `wiki_apply` schema](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/apps/mcp/src/server.ts#L746-L811) 没有该字段，调用方无法传入**生成本次改动所依据的旧 revision**。系统内部仍有事务和版本检查机制，不能说完全没有并发保护；但其 [引擎 README](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/README.md#L13-L23) 说明省略期望修订时，替换字段可 last-writer-wins。多 session 同写需按真实链路测条件更新/审阅合并。

**导出、许可证、成熟度。** [OKF 导入导出](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/packages/wiki-engine/src/okf.ts) 是源码实现，Wiki MCP 暴露导出；[许可证](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/LICENSE) 为 Apache-2.0。仓库有 Wiki 路由/引擎/MCP 测试与 [compose smoke](https://github.com/romiluz13/mdbrain/blob/8dafa12d17206ef7cb0b7034f04c9fee1db030e6/README.md#L120-L205)，证明维护者写了可执行路径；**本轮未运行，不能证明它在本机可部署或高负载稳定**。完整 bundle 需 MongoDB Atlas Search、单独 Memongo（版本锁定）；无模型 key 可走降级文字检索，详见 README 同段。

## 2. lucasastorian/llmwiki：hosted 与外置 local vault 均可独立于开发仓库

**思想与实际存储分叉。** [README](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/README.md) 明确称受 Karpathy 思路启发，[VaultFS 接口](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/mcp/vaultfs/base.py) 有知识库、文档、来源引用与 stale 查询抽象。[本地实现](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/mcp/local_server.py#L1-L3) 明说“Filesystem is truth. SQLite is the index”；[README 的目录图](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/README.md#L124-L145) 进一步确认，且示例是开发仓库外的 `~/research/`。这符合用户最新允许的独立 Markdown vault。[hosted PostgresVaultFS](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/mcp/vaultfs/postgres.py#L173-L204) 则把 Wiki 文本插入 `documents.content`，原文件/资产由 S3 处理；`write_to_disk` 在该实现为空操作。两种形态均值得按实际部署条件验证。

**接口与治理。** [hosted MCP](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/mcp/hosted.py#L65-L103) 是 HTTP transport；[README 工具表](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/README.md#L147-L179) 列 create/edit/append/search/read/lint 与多知识库。Postgres 查询用 `knowledge_base_id` 和 `user_id` 过滤，[示例](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/mcp/vaultfs/postgres.py#L135-L171) 支持用户内多个 KB。来源引用图可以查未引用来源和被标记的过时页；[lint 代码](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/mcp/tools/lint.py#L121-L140) 主要查 frontmatter、引用、链接、孤页与 stale。README 的自维护靠外部 Claude Routine 定时调用，并非内置冲突裁决或稳定任务调度。

**并发、导出、成熟度。** [edit 工具](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/mcp/tools/write.py#L313-L362) 先读正文、做字符串替换再写；[Postgres 更新](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/mcp/vaultfs/postgres.py#L206-L265) 虽锁定当前行并递增 `version`，但不比较调用者读到的版本，两位 agent 顺序提交仍可覆盖。未在公开 MCP 工具中核到整库导出或可靠增量事件流；不能把可读页面等同可完整迁移。仓库 [Apache-2.0 许可证](https://github.com/lucasastorian/llmwiki/blob/f102a812f3e2bd35a02dbae03b9f88ba33f658db/LICENSE)、[hosted/local 服务与部署文件](https://github.com/lucasastorian/llmwiki/tree/f102a812f3e2bd35a02dbae03b9f88ba33f658db) 俱全；公开项目近期仍在改动，本轮未运行其部署/隔离/并发测试。

## 3–6. 独立 Markdown vault 候选与路径约束

**Microsoft `llmwiki`。** [README](https://github.com/microsoft/llmwiki/blob/e09126f257c1fcf8e63234382748a51cf6a5df7f/README.md#L226-L253) 清楚定义 raw sources、LLM-owned Wiki、schema 三层；[MCP 文档](https://github.com/microsoft/llmwiki/blob/e09126f257c1fcf8e63234382748a51cf6a5df7f/README.md#L322-L380) 有读写/增量摄入/lint 工具。它默认初始化 `<workspace>/.wiki/`（[README](https://github.com/microsoft/llmwiki/blob/e09126f257c1fcf8e63234382748a51cf6a5df7f/README.md#L287-L308)），因此若 VS Code 工作区就是 evoLoop 开发仓库则不符合路径约束；独立 Wiki 工作区是否顺畅供所有 session 使用尚未实测。MIT [LICENSE](https://github.com/microsoft/llmwiki/blob/e09126f257c1fcf8e63234382748a51cf6a5df7f/LICENSE)。

**Alexander Makarov `llm-wiki`。** [README](https://github.com/AlexanderMakarov/llm-wiki/blob/9078f12e182e227de54bdd2413f7419e2a814854/README.md) 直接说实现 Karpathy 模式，摄入 Codex、Claude Code 等 session，用 MCP `wiki_search/read_page/sync/export/add`，有候选审阅门与静态站，正好能参考“各 session 贡献→维护者审阅”的流程。其统一存储是可另选位置的 Markdown vault，**按用户最新要求可以作为独立认知系统候选**。MIT [LICENSE](https://github.com/AlexanderMakarov/llm-wiki/blob/9078f12e182e227de54bdd2413f7419e2a814854/LICENSE)。本轮未验证它的候选审阅对相互矛盾结论的实际处理强度。

**LangChain `OpenWiki`。** 较高的社区关注度值得纳入比较，且它**不只是静态 codewiki**：[README](https://github.com/langchain-ai/openwiki/blob/6c14bff27830034bfd70c15bde46825d7686ec60/README.md#L19-L32) 描述增量维护和有来源的 Claims，且提供 code 与 personal 两种模式；[模式说明](https://github.com/langchain-ai/openwiki/blob/6c14bff27830034bfd70c15bde46825d7686ec60/openwiki/concepts/two-modes.md#L45-L73) 与 [实际路径配置](https://github.com/langchain-ai/openwiki/blob/6c14bff27830034bfd70c15bde46825d7686ec60/src/config/openwiki-home.ts#L39-L49) 一致：code 权威写入仓库 `openwiki/`，personal 权威写入用户目录 `~/.openwiki/wiki/`。**personal 路径满足独立于开发 repo 的要求**，并可接多种外部来源；[MCP server](https://github.com/langchain-ai/openwiki/blob/6c14bff27830034bfd70c15bde46825d7686ec60/src/integrations/mcp/server.ts#L11-L45) 所述 host-driven 页面生成则要求 agent 用原生仓库工具写 Markdown，README 也明确目前只支持 repository code wiki，不能将这条链路直接等同 personal 模式的多 session 写入。MIT [LICENSE](https://github.com/langchain-ai/openwiki/blob/6c14bff27830034bfd70c15bde46825d7686ec60/LICENSE)。其来源追踪/可恢复任务协议值得验证。

**nashsu `llm_wiki`。** [README](https://github.com/nashsu/llm_wiki/blob/48fd970e206a02a6d2028d1dbfc41b7a0345bf0b/README.md#L53-L79) 明确引用 Karpathy 模式，是跨平台桌面应用，用户选择 Wiki 项目文件夹，生成 Markdown/Obsidian 兼容 vault；可将该文件夹放在 evoLoop 开发仓库外。[MCP README](https://github.com/nashsu/llm_wiki/blob/48fd970e206a02a6d2028d1dbfc41b7a0345bf0b/mcp-server/README.md#L1-L19) 指明它代理正在运行的桌面应用本地 HTTP API；[工具清单](https://github.com/nashsu/llm_wiki/blob/48fd970e206a02a6d2028d1dbfc41b7a0345bf0b/mcp-server/README.md#L55-L75) 有项目绑定、文件读取、Review 列表、搜索、聊天、图与来源重扫，多项目绑定可固定单个 MCP 进程所见项目。**目前未核到 MCP 中供各 session 直接 create/edit Wiki 页的工具**；[MCP server 源码](https://github.com/nashsu/llm_wiki/blob/48fd970e206a02a6d2028d1dbfc41b7a0345bf0b/mcp-server/src/index.ts#L31-L179) 也只注册上述工具。它的 [HTTP API](https://github.com/nashsu/llm_wiki/blob/48fd970e206a02a6d2028d1dbfc41b7a0345bf0b/src-tauri/src/api_server.rs#L353-L369) 有 Review 更新端点，是否足以承载“各 session 贡献认知→Wiki session 维护”需要专项验证。实际 [LICENSE](https://github.com/nashsu/llm_wiki/blob/48fd970e206a02a6d2028d1dbfc41b7a0345bf0b/LICENSE) 是 GPLv3；GitHub API 的许可证字段为 NOASSERTION，应以文件为准。

**本段历史判断的修正：** 上述 MCP 工具清单与源码阅读未覆盖实际写页入口；后续固定版本核查和运行已证实 `llm_wiki_write_page`。仍不能由“可写页”推出冲突自动合并、已变更来源自动修订全部旧页，或多 session 共写安全，详见[功能与流程比较](../references/wiki-feature-comparison.md)。

## 建议的最小验证门槛

若进一步评估 **lucas 的外置 local vault 或 hosted 知识库**，可给它一个独立测试空间，不输入真实 evoLoop 敏感材料：两个模拟 session 分别写“有来源的新认识”、同一页并发修订与过时来源，再由模拟 Wiki 维护 session 经 API/MCP 检查引用、stale、lint 并修订。重点查完整导出/迁移、跨项目隔离、并发覆盖，以及维护者是否能保留互相冲突的说法直到有证据裁决。并行做小型接口核验：OpenWiki personal 能否由多个外部 session 向同一 vault 稳定贡献；nashsu 能否通过桌面 API/MCP 写页并处理 Review。MDBrain 仅作治理实现对照或备选验证，尤其须测中文冲突、HTTP `expectedRevision` 与 Memongo/Atlas Local Preview 成本。此处仅是验证设计，**未做上述试验**。
