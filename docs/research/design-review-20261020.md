# 多角度设计审阅与首个工作切片

2026-10-20。问题是：既有设计是否足以开始实施，哪些边界若不修正会在真实工作中失败？审阅基线是 `2547b4b`；用户已授权多角度审阅后修正并实现（DEC-028）。本报告记录设计判断、实际实现和有限验证，完整目标仍由产品与架构正文维护。

## 审阅怎样组织

三位独立 Agent 分别检查产品与阶段、数据与恢复、前端与知识后端边界；主会话整合接口、实现与使用验证。实现后另由未参与编写的 Agent 做只读代码审查。各方向覆盖相应正式文档与已有研究，未重新审计全部原始历史、重新运行 Wiki 实验或引用上游 benchmark 作为本产品验收。

| 角度 | 发现与实际影响 | 本次处理 |
| --- | --- | --- |
| 产品目标与阶段 | “需求改版”若不区分草稿和采纳，会让未确认意见影响已接受任务；首片若承诺 Git/Wiki，会越过尚不存在的读取能力 | 只有已采纳版本触发 ready 任务复核。首片 S1a 限过程 Markdown；后续 S1/M1 继续保留 |
| 数据模型 | 改写任务原依据会抹去当时为什么这样做；关系端点改写也会混淆历史 | 不可变 Task/DocumentRevision、封存 BasisSet；新的选择形成新任务修订。关系重定向产生新关系身份 |
| 命令与事务 | operationId 单独去重不足以拦截“同 ID 换意图”；合法拒绝与数据库故障混淆会误判失败 | 身份＋规范化命令哈希；业务 savepoint 回滚后保留拒绝日志，未知基础设施结果不登记为业务拒绝 |
| 未来飞书恢复 | 首次创建丢回执时若无稳定远端标记，无法确定是否已建，盲重建可能重复 | 设计补充首次投影的关联标记与核对；未冒充已接入飞书 |
| 前端与知识 | 图谱历史查询容易用当前关系冒充历史；Git 固定版本读取被隐含承诺 | 明确 focusRevision 与历史关系能力；Git 来源适配器列为后续切片，知识 API 与供应商解耦 |
| 代码与出站事件 | 旧影响被 superseded，但最初实现只发新影响事件，未来投影可能留下旧待办 | 两条替换路径均发旧影响 superseded 事件，增加回归用例并经独立审查确认 |
| 界面恢复 | 单一未知操作状态会被另一项覆盖，刷新丢恢复入口 | 多回执列表，绑定身份/项目/任务；仅持久化恢复索引，同任务未确认前禁止新提交 |

结论是当前方向可支持一个真实的首片，而不是所有设计已经被证明正确。知识维护质量、角色演进、跨 session 消费、平台同步和长期效果仍需各自的实际证据。

## 实现范围与包边界

| 已实现部分 | 负责什么 | 不依赖什么 |
| --- | --- | --- |
| contracts | 浏览器可读的数据/命令 schema；独立 server ports 出口 | PG、Fastify、平台 SDK |
| core | 采纳、任务接受、固定依据、影响复核、权限、命令重放 | SQL、浏览器、OpenViking URI、飞书 record ID |
| adapter-postgres | 显式表、迁移、项目外键、封存/不可变约束、事务和出站记录 | HTTP、React |
| coordinator | 令牌身份、共同 API、进程独占和同源静态入口 | UI 业务状态 |
| cli | 校验并调用共同 API，按操作 ID 查询 | 数据库连接、第二套状态机 |
| workbench | 表格、原件阅读、版本比较、采用/保留理由、历史依据和未知回执 | SQL、平台凭据、模型执行 |

S1a 使用 Node 24、TypeScript、Fastify/Zod、真实 PostgreSQL 18 与 pg/node-pg-migrate、React/Vite。精确依赖在锁文件；选择依据见[技术选型](../architecture/technology-selection.md)，正常运行见[本机运行](../development/local-run.md)。没有复制 nashsu 源码；图谱和 OpenViking 适配仍属于后续工作。对象存储边界已设计，本次内联 Markdown 不需要先安装对象服务。

## 实际验证

输入是特意构造的过程文档阅读需求，不包含私人会话或真实项目原件。数据库使用隔离的 PostgreSQL 18.6，API 测试使用真实驱动与迁移；core 单元用例使用可控端口替身。不能把两种证据混称。

| 检查 | 已观察结果 | 能证明的范围 |
| --- | --- | --- |
| 文档候选与采纳 | r2 草稿不产生影响；采纳后出现两项待复核 | 当前过程 Markdown 到 ready 任务的关联传播 |
| 不同任务作不同选择 | A 采用新版，B 保留旧版且保存理由；两者仍 ready | 复核与执行/完成分开，旧 TaskRevision/BasisSet 可回查 |
| 竞争与重放 | 同基线竞争一个接受、一个拒绝；同操作重放结果一致，换内容拒绝 | PG 内的命令身份与版本保护 |
| 故障回滚 | 在最后写 outbox 时注入错误，正文与操作日志均未留下半成品 | 同一 PG 事务原子性，不涵盖外部网络副作用 |
| 数据库约束 | 跨项目关联、旧修订修改、封存集合改写等被拒绝 | 当前迁移及被测表约束 |
| 权限 | 请求自报身份无效，跨项目/旧版/他人操作读取受限 | 配置令牌模式；非生产用户认证 |
| 浏览器普通入口 | 登录→表格→比较→A 采用/B 保留→旧任务依据→完整历史文档 | 真 API 与 PG 下的有限 Agent walkthrough；非真人满意度 |
| 写成后响应丢失 | 本机故障代理在 PG 提交后隐藏成功回包并返回 503；两项回执并存，刷新/重新登录后逐项按原 ID 查到已应用 | 浏览器真实恢复路径；代理故障注入，不是外部平台实测 |
| 进程独占失效 | 第二协调者被拒绝；终止测试库锁连接后旧资格失效，可重新取得 | 专库连接级独占；不是分布式 fencing |
| 窄屏读取 | 390px 视口页面无整体横向溢出，表格在自身区域横向滚动；全文与决定可读 | 本机浏览器尺寸检查，不是手机远程服务 |
| 在途刷新与暂时失联 | 发送前保存回执；刷新与服务中断后仍能恢复并按原 ID 核实已应用；读取恢复按钮可解除旧错误 | 当前本机浏览器恢复；关闭标签页的恢复索引仍可能丢失 |
| 过期界面 | 另一提交先改变任务版本后，旧界面提交拒绝，草稿保留、提交禁用、恢复回执清除 | 版本竞争下明确重新判断，不自动覆盖 |
| CLI | 经共同 API 实际创建一份合成候选文档并读取列表 | CLI 真实读写，无直连 PG |
| 独立代码审查 | 检查重放、旧版拒绝、多文档复核、封存和身份绑定，发现并确认修复出站事件遗漏 | 静态审查及已有用例范围，不等于穷尽验证 |

本地构建、类型检查、39 项文档测试、13 项应用单元测试、13 项数据库/集成检查通过；文档检查与构建覆盖 52 页、9 项资源。远程 CI 以对应提交的检查结果为准。远程合入、生产部署和用户接受不是本报告推定的结果。

## 留下的边界与下一阶段

- 当前支持 ready 任务复核；运行中或已完成任务的变更影响、任务派发、验收、通知和实际消费尚未实现。
- 过程 Markdown 按原文阅读；HTML/附件、Git 固定提交读取、知识图谱和 OpenViking 读写未开放。S1a 不代表完整 S1/M1。
- 详情历史或关联任务扫描超过 10,000 条会明确拒绝，避免静默截断。接近该量级之前需历史分页、pending-only 查询及分批影响传播，不能宣称已支持长期大规模项目。
- 当前单协调者锁只服务本机启动与连接失效保护，未证明分布式 fencing、自动故障转移、备份恢复或外部副作用恰好一次。Outbox 尚无真实消费者。
- 本机访问令牌、临时回执与合成样本不证明公网多用户安全或持续产品收益。知识系统的有效性还要核对纠正、来源撤回、矛盾整合和新 session 是否采用，不能用本次 CRUD/复核测试替代。

下一次应先让实际负责人与领域 session 使用这条依据复核路径，观察哪些工作真的因此改变，再按目标补齐 Git 来源、任务运行及消费、外部投影或 Wiki 之一。新增职责和技术层都需要这类实际负担与收益证据。
