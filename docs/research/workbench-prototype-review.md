## 检查与后续工作

原型仅在本页模拟导航、筛选、状态变化和按钮反馈；刷新会重置。已检查内联 JavaScript 语法及十个视图的合成状态路径；另在真实浏览器操作了提议与补证、需求版本比较和 r2 采用后保留 r1、分工替代选择与撤回、日程暂停、运行未知/同步冲突、逐 case 评价及 Wiki 搜索空态。

Wiki 浏览器路径检查了历史 v2 候选不可直接发布、来源不可核对时停住、恢复来源后的独立发布、未知结果先核对、返回 v4 后模拟已读但采用仍待验。集成检查据此补上候选基线绑定、来源/基线发布阻止，以及列表、详情和异常页的状态一致性。桌面阅读/Review/评价及 390px 手机知识/评价页完成目视检查；手机菜单可切换，十个视图无整页横向溢出。原型目前仅演示一个临时候选，未实现完整候选历史、全部历史修订回读或权限变更场景。

后续文档分类澄清检查了整理面板的审阅、合并、构建三个独立阶段，以及原有 r2 采用后仍保留 r1 的路径；桌面与 390px 手机整理面板完成目视检查，手机无整页横向溢出。[项目数据](../architecture/project-data.md#3a-工作文档怎样沉淀为仓库正式文档)的新流程图在浏览器渲染成功。同步补充产品定义、文档维护、领域合同、存储、前端、包架构和知识流；自动化整理仍是待实现设计。

用户随后指出，上述版本虽区分了文档用途，却仍把 repo 文档纳入了 Document Table，设计并不符合其范围要求。DEC-023 因此收窄文档表和目录；前述界面检查仅证明当时模拟可运行，不证明用户认可该分类。当前目录以过程文档及 Task 直接关联为准，仓库 `docs/` 独立维护。

本次纠正后的浏览器检查确认：目录只列 DOC-021、DOC-018 两份过程文档；两者均能与关联 Task 往返跳转；侧栏仓库入口实际打开独立产品报告。工作台、存储、知识流和项目数据图均可渲染；390px 过程文档页无整页横向溢出。真实 link 保存、仓库来源解析与数据库约束仍未实现。

这些是界面和模拟路径证据，不是用户亲用或服务验证。尚未实现后端、权限、持久化、真实 Wiki/飞书/Codex API，也未覆盖每条产品路径的完整异常分支。将来做真实产品时，要用固定修订、授权、幂等请求和可回读结果替换页面内状态，并以独立消费与实际用户效果检验价值。
