# nashsu/llm_wiki 的接入边界

> **研究记录，非正式选型。公开整理版：2026-10-19。原始运行证据外置、未发布；本次公开整理未重新运行实验。** 阶段：基于当轮实测提出的接入边界（历史判断；非当前架构承诺）。

2026-10-19。当前不建议直接作为多session共享认知的权威底座；可作为人类阅读/整理入口的候选，或进行受限的外部维护试点。并发覆盖、过时页和撤回后残留正文均已复现；手动备份恢复已通过，原生UI归档仍未验证。此结论是当轮直接采用判断，不等于后续不得 fork 修补；固定版确有 MCP `llm_wiki_write_page` 和 HTTP `/pages/write`，但两者均不提供调用者旧版本条件写。此结论不评价另一个候选。

## 已核实的接口与责任

| 参与者 | 可用路径 | 实际保证 / 边界 |
| --- | --- | --- |
| 业务session | 放入独立项目 raw/sources 后Source Watch/rescan，或本地19827/clip提交文本；用HTTP/MCP写wiki页 | 多个来源可提交，自动队列负责摄入；新增概念页不等于所有受影响认识已修订。直接write默认create-only，覆盖无CAS |
| Wiki维护session | 正常读取、搜索、Review列表；HTTP pages/write或MCP write_page | 可以实际修订Markdown，综合/争议语义依赖维护者和提示词；Review resolve只标状态，不执行UI动作 |
| 新session | MCP/HTTP search→read→下钻raw来源；引用页和来源路径 | API/MCP要求桌面App持续运行。应pin稳定项目UUID，不使用会随UI切换的current。正文历史默认关闭且HTTP无历史读取接口 |
| 人类 | 独立vault、桌面知识树、认识预览、来源/Related/Edit、Review界面 | Markdown可直接阅读；本轮观察到失效Related链接。完整纠错操作与用户真实体验尚未验收 |

## 所需的最小接入合同

认知、checkout、依赖、索引、日志与备份留在外置知识空间；开发仓库只保留正式方案/规范和接入文档。原始业务证据不经助手改写替代，只追加稳定ID、来源、时间、内容摘要hash与适用边界。正式文档可以引用当前认识，不把认知正文同步进开发repo。

业务session均可形成认识和负责自身领域修复。维护者比较已有认识、新来源及不确定性并修订关联页，不成为全项目审批者。分工管理session根据实际使用、目标与容量证据提议职责试行；任务状态和职责调整的行动权威仍是飞书，不另建任务数据库。

现有write接口不比较调用者基线，不能让多个session自由覆盖同一页并宣称安全。试点必须约定同一页串行维护、提交前重新读、写后核对、超时先读回；这些只是流程限制，不是跨进程CAS保证。生产化需要另行验证的条件写入/变更提案入口，不能用进程内锁替代。

外部Wiki维护试验使用新增维护提示词与薄HTTP入口脚本，独立Agent分两批完成27次原生API写入；新消费者能完成任务。但不少写入丢失sources字段，尚不能与原生来源级联可靠协作。未来接入必须验证机器依赖字段、来源撤回与修订语义；本轮没有补齐。它的成绩单列为额外适配，不等同产品原生自动编译，也未补齐并发强约束。

## 模型与凭据

产品配置/凭据原生来自应用级app-state.json，HTTP聊天即使开放只读仍要求token。验证使用原有环境变量经仅loopback凭据转发层注入真实provider，密钥不落vault/证据/备份。模型耗尽或厂商协议变更必须显式失败，不能将未完成摄入记为成功。本轮曾因余额不足阻塞，用户确认充值后恢复。正式运行应选择可维护的凭据注入方式和预算责任，不复用验证脚本当生产服务。

项目归档从源码看包含隐藏项目状态、Review、历史等，并跳过symlink；应用级配置/凭据不在项目包。文件历史默认关闭；保存的log.md不是不可变的版本审计。本轮普通ZIP项目备份58文件哈希一致、重启后来源/关键查询/Review可读；应用级配置和凭据不在项目包。原生UI导入导出未实测，向量索引未启用。

## 尚不能承诺

- 多写者条件更新、超时重试幂等与跨进程协调。
- 新来源自动修订所有受影响认识，或撤回来源后自动撤销正文中的主张。
- 无桌面进程的独立HTTP/MCP服务。
- 长期真实业务使用收益、中文大库检索质量、用户对维护体验满意。
- 原生UI归档导入的完整实测；手动备份与原生读取已通过，结果不能换成原生归档按钮通过。


## 是否继续试点

小样本中，直接原材料、原生Wiki、外部维护Wiki的消费者产物都满足要求；Wiki路径没有显示效率优势，且增加模型摄入、维护和桌面保活成本。现阶段不应仅凭消费者答对就迁入真实历史或让所有session直接覆盖知识页。若主要需求是人阅读和有序整理，可用非权威测试库继续真人体验；若要共享认知底座，应先解决已复现的修订、来源失效和条件写入问题，再按同协议重验。

没有因此改变飞书任务权威、动态职责设计或业务session的领域判断权；也没有据本候选结果替另一个候选作结论。三组产物的公开观察与外置证据名见同目录[实测结果](results.md)；原始产物未发布。
