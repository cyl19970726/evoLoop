# 设计系统与共同交互：稳定外壳，逐层阅读

2026-10-30 · 前端目标与阅读合同。页面能力是否已实现、部署或通过消费者使用，以[阶段路线](../roadmap.md)和对应版本的验证为准；下列界面要求不把目标能力写成当前服务事实。

## 共同视觉语言

双层左栏采用轻量浅色 B2B 阅读密度：外层是稳定模块，内层随项目显示当前上下文，可收起；图标配中文名称。界面不使用绿色（含青绿、薄荷绿和绿色状态标签），主动作使用克制的蓝色。默认先读列表、详情、全文，再按需打开新建、编辑、判断；没有真实数据或能力时明确空态，不用虚构人员、搜索或统计填充。总览内容按真实工作、知识可读能力及使用反馈逐步核定，具体主次见[总览页面](pages/overview.md)。

保留现有两条左栏：外层为稳定模块，内层给项目上下文和当前团队入口；历史和低频配置可展开，异常入口持续可见。沿已选任务页的清晰行、安静排版、所选摘要联动演进；既有方向图是视觉参照，其示意人数、任务和状态不能写入产品数据。

正文、标题、次级事实和原始标识要有清楚层级。列表突出对象名称、真实状态、具体责任和下一动作，ID/hash放可到达的来源层；详情优先当前问题与证据，完整正文、图表与固定原件必须可读。颜色辅助文字，不靠状态圆点表达唯一含义。蓝色承载主动作，紫色用于次级阅读，等待与失败使用有文字的中性或暖色提示；执行中的代码若与已定无绿色约定不符，应在界面优化中校正，不以示意图推翻规则。

## 共用状态语言

| 要区分的事实 | 界面表达与来源 |
| --- | --- |
| Task 的四态与工作进度 | todo/in_progress/done/cancelled是业务状态；待承接、受阻、待验收等说明当前事实，附原因和下一责任 |
| Role、分派与实际实例 | Role 是持续职责；assignment 的目标和接受回执才说明具体承接，同 Role 关系不推定执行 |
| Session 与 Run | Session ready不等于Run running；队列占用另列。分派回执、Run认领与当前执行不要共用含混的“已接手”标签 |
| 当前与历史 | 已完成/已取消Task保留的assignment、Run和Session入口明确标历史；Session现状不代表该Task仍在执行 |
| 技术检查与使用 | Delivery的产物/技术检查、当前交付的Agent或真人使用观察和有权者关闭各自显示 |
| 消息与同步 | 已保存、已发送、已读、已采用和有效分别留证，不从通知、合并或发布推定消费 |

业务字段及转换条件以[共同合同](../architecture/contracts.md)为准；本表只约定如何让人辨认，不在浏览器增加另一套状态机。

## 读取、操作与失败

读取显示观察时间与范围。重新读取时保留上次内容并标正在核对；失败明确旧数据仍在，不能变成正常空态。没有对象、无权、后端不可达、固定原件缺失和操作结果未知分别说明原因及可行下一步。技术错误可展开核诊断，默认层用用户能理解的文字。

列表搜索说明覆盖已载入页、服务端搜索或完整分页，未读完不宣称全量。单元格链接、行选择和打开详情各自有明确语义；标题与主入口支持键盘，表格不能让行点击吞掉关联Task链接。详情首帧核项目和对象身份，标题、正文、成果、错误及链接不得跨对象拼接。

写入只连接已有且有权调用的API。缺权限或能力时给原因；常规工作可回到现有Agent经CLI完成，不以大表单迫使人接管流程。保存草稿与operationId；未知结果按原操作查回，不新建ID盲重试。危险/低频动作进入明确操作层，保持来源、授权和业务效果可核。

## 桌面、手机与阶段范围

**桌面**保留全局导航、列表与详情并排；适合对比需求修订、Wiki 全文/来源/相关认识、两个任务和外部编辑冲突。知识空间可让专题目录、正文和来源侧栏三栏协作，图谱单独展开，不压缩正文。侧栏讨论材料可逐条打开证据，但不会在工作台内伪造 Codex 聊天内容。键盘操作和对象固定链接帮助人定位；Agent 常规读写走共同 API 的业务入口，浏览器走读用于界面验收。**手机**优先首页待判断、讨论准备、任务状态、知识卡片和异常处理；任务等列表可改卡片，过程文档仍按[表格阅读约定](pages/documents.md#从表格打开完整过程文档)保留表格、横向查看或收起次要列。完整知识页仍能按“正文 → 来源 → 相关认识 → 版本/纠错”顺序展开。版本差异与来源保留完整内容及固定修订链接，允许横向查看或转桌面继续；不因窄屏隐藏反例、权限和冲突。高风险采纳/撤回须显示影响对象和确认后的状态，不能靠滑动误触。

单片、阶段与整套工作台的完成单位及分期验收，仍由[产品判据](../product/workbench.md#分期与整体完成判据)维护。

## 组件和验收的一致性

复用对象引用、版本提示、状态标签、读取反馈、折叠来源、表格/窄屏语义块和返回入口。共享模式服务于清楚的数据流，不要求给每一类业务事实发明一个框架。实际实现边界见[前端架构](architecture.md)。

按受影响页面核1171×635桌面与390px窄屏，并按实际使用补视口；看标题、状态、责任、下一步和入口是否可读，分别检查整页溢出、正文/图内部滚动及键盘焦点。保留初次失败和修复复测。作者视觉自检、合成组件回归、真实API操作、独立Agent使用和真人审美反馈分别报告。
