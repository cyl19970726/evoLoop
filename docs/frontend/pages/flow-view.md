# 动态：调度的数据流怎样一眼看清

“统筹安排 › 动态”把 Leader 和各智能体之间的消息、任务、交付怎样传递、状态怎样变化画成一张图（[DEC-045](../../decisions.md#用户已确定的方向) 调度板给人看的版本）。**现状：设计与夹具已做（F1 第一段），只在样例页 `/ui/flow` 用手写夹具运行，没有接真实数据；** 真实快照、事件流和订阅在 Q2 发布后接入（第二段）。夹具通过不算验收，画面上始终写“夹具数据 · 非真实”。

## 这一页回答什么

- 此刻调度卡在哪里：哪个队伍项挂起、哪个 Session 受阻、哪个通知包没送到？
- 一条消息、一个任务、一份交付是从谁传到谁的，状态怎样变了？
- 对象走到哪一步了：待派发、队伍、运行中、待验收、已验收、已合并、已发布各有几个？

## 布局

| 区域 | 放什么 |
| --- | --- |
| 左 | 人与系统：使用者、需求 Session、定时代班、结果通知、其他身份（身份认不出的事件画在这里，并写“端点未识别”） |
| 中 | 调度板（待派发、队伍、运行中、待验收、卡住的地方）；其下是 Leader 卡片；再下是通知包托盘 |
| 右 | 每个 Session 一张卡：职责、状态（图标加文字：运行中、排队中、受阻、空闲、读不到）、当前任务；多于 7 个时写“另有 N 个”，去统筹安排看全部 |
| 底 | 对象轨道，每一步一个数量 |
| 下 | 事件列表（新的在上，与画面同步）和详情；控制条：回放 / 暂停、时间滑杆、按种类筛选、只看卡住的 |

宽屏是画布；窄屏（≤640）改为纵向泳道：节点、对象轨道、列表依次排下，没有页面横向滚动。总览加的小卡片（写卡住的地方和最近几条事件）链到这里。

## 内容与状态

- 每个事件是一个带符号和文字的小包，沿路径移动；种类对应的符号、颜色与文字见 `flowModel.ts`，颜色沿用工作台语义（蓝：进行；琥珀：等待；红：受阻；陶土：通知包与放行），**不用绿色**，颜色之外总有符号和文字。
- 路径由事件的 Session 与 `from`、`to` 决定：通知经托盘到 Leader；派发从 Leader 到 Session；交付从 Session 到结果通知；认不出的 Session 不猜。
- 数量只取自快照，读不到写“读不到”，不写 0；事件流今天不含合并与发布，这两步写“读不到”。未知的事件种类写“未知事件”和它的名字。
- 同时最多 12 个包，多的合成一个“×N”，N 是精确条数。回放位置决定画面：同一位置总是同一状态。
- 减少动态效果：不播放流动，只闪节点并更新列表。标签页在后台不推进、不画包，回到前台从原位置继续（实时模式按事件补齐状态）。
- 键盘：每个节点和每行事件都是按钮，Tab 可达，Enter 看详情；详情写时间、种类、从谁到谁、对象、状态变化，并给可打开的真实对象链接（夹具没有）。

**性能预算：** 只用手写 SVG 和 CSS，不引入图库；页面按路由懒加载，其他页的包体积不变；前台回放时主线程超过 50 毫秒的长任务为 0；同屏包不超过 12；只在页面打开时订阅，离开即断开（第二段接入时验证）。

## 事件到画面（第二段接真实数据时的约定）

| 数据 | 画面 |
| --- | --- |
| `notice.created / packed` | 结果通知 → 托盘 |
| `notice.sent / delivered / seen` | 托盘 → Leader；`next` 为 `steer` 写“送入当前一轮” |
| `task.queued / turn / run_*` | Leader → Session；轨道上相应的数量变化 |
| `task.delivered`、`acceptance.*` | Session → 结果通知；`blocked` 标红 |
| `message.*` | 发送者 → Leader 或 Session；`inserted` 与 `queued` 用不同符号 |
