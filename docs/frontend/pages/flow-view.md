# 动态：调度的数据流怎样一眼看清

“统筹安排 › 动态”把 Leader 和各智能体之间的消息、任务、交付怎样传递、状态怎样变化画成一张图（[DEC-045](../../decisions.md#用户已确定的方向) 调度板给人看的版本）。**现状：** 第二段已做，读调度板的真实快照、事件窗口和 SSE。样例页 `/ui/flow` 仍用夹具，画面写“夹具数据 · 非真实”，夹具通过不算验收；正式实例复核等调度板发布后另排。

## 这一页回答什么

- 此刻调度卡在哪里：哪个队伍项挂起、哪个 Session 受阻、哪个通知包没送到？
- 一条消息、一个任务、一份交付是从谁传到谁的，状态怎样变了？
- 对象走到哪一步了：待派发、队伍、运行中、待验收、已验收、已合并、已发布各有几个？

## 数据怎么来

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 快照（Session、队伍、待派发、通知包、各步数量） | `GET /work-board` | 打开页面时读一次；之后每来事件，1.5 秒防抖后重读，让数量跟上 |
| 事件窗口 | `GET /work-board/events?from=近 6 小时&limit=500`，按 `cursor` 继续，最多 8 页 | 窗口内事件太多时最早的一部分读不到，画面上写明 |
| 实时 | `GET /work-board/stream?after=<已应用的最大序号>`（SSE） | 浏览器的 EventSource 带不了登录用的 Authorization 头，所以用 fetch 读同一个 `text/event-stream` 并自己解析；序号小于等于已应用的事件直接丢弃，所以重连既不丢也不重 |
| 断线 | 流断开后画面写“连接中断，正在按序号续传（从 #N 之后）”，1、2、4…最多 15 秒的间隔重连；服务说位置已过期（`reset`）时整个重读 | 已重连次数写在画面上 |
| Leader 是哪个 Session | “安排”页读的智能体目录里职责模板为 `lead` 的那个 | 目录读不到时 Leader 的事件画在普通 Session 卡上，不猜 |
| 订阅的时机 | 动态页签打开且页面在前台（已访问的页面是隐藏保留的） | 切到“安排”页签、离开统筹安排或切到别的空间即断开；后台标签页不画包、不推进回放，回到前台按事件补齐 |
| 事件两端的身份 | 事件自己说的：安排验收的接收者、交付的签字者是事件所指 Session 的身份；安排验收、关闭、复核、预留 Run 的是 Leader | 其余身份写“其他身份”，详情里写“端点未识别” |

## 布局

| 区域 | 放什么 |
| --- | --- |
| 左 | 人与系统：使用者、需求 Session、定时代班、结果通知、其他身份（身份认不出的事件画在这里，并写“端点未识别”） |
| 中 | 调度板（待派发、队伍、运行中、待验收、卡住的地方）；其下是 Leader 卡片；再下是通知包托盘 |
| 右 | 每个 Session 一张卡：职责、状态（图标加文字：运行中、排队中、受阻、空闲、读不到）、当前任务；多于 7 个时写“另有 N 个”，去统筹安排看全部 |
| 底 | 对象轨道，每一步一个数量 |
| 下 | 事件列表（新的在上，最多列最新 200 行，更早的用时间滑杆回放）和详情；控制条：实时 / 暂停 / 回放、时间滑杆、按种类筛选、只看卡住的 |

宽屏是画布；窄屏（≤640）改为纵向泳道：节点、对象轨道、列表依次排下，没有页面横向滚动。总览加的小卡片（写卡住的地方和最近几条事件）链到这里。

## 内容与状态

- 每个事件是一个带符号和文字的小包，沿路径移动；种类对应的符号、颜色与文字见 `flowModel.ts`，颜色沿用工作台语义（蓝：进行；琥珀：等待；红：受阻；陶土：通知包与放行），**不用绿色**，颜色之外总有符号和文字。
- 路径由事件的 Session 与 `from`、`to` 决定：通知经托盘到 Leader；派发从 Leader 到 Session；交付从 Session 到结果通知；认不出的 Session 不猜。
- 数量取自快照，读不到写“读不到”，不写 0；“已验收”是所读窗口内关闭的任务数，格子本身标注“近 N 小时”（夹具写“窗口内”），不是总数；事件流今天不含合并与发布，这两步写“读不到”，等真实事件出现再显示。未知的事件种类写“未知事件”和它的名字。
- 同时最多 12 个包，多的合成一个“×N”，N 是精确条数。包走到目标旁边后停 6 秒，可点它看详情（键盘和读屏走事件列表的同一行）。回放位置决定画面：同一位置总是同一状态。
- 三种模式：实时（每来一条画一个包）、暂停（画面不动，只提示又来了几条）、回放（每 0.8 秒一条）；在末尾点“从头回放”游标回到起点并真的播放。
- 减少动态效果：不播放流动，只闪节点并更新列表。标签页在后台不推进、不画包，回到前台从原位置继续（实时模式按事件补齐状态）。
- 键盘：每个节点和每行事件都是按钮，Tab 可达，Enter 看详情；详情写时间、种类、从谁到谁、对象、状态变化，并给真实对象的链接（见下“对象链接”）。

**性能预算：** 只用手写 SVG 和 CSS，不引入图库；“动态”页和总览小卡片各自是独立的代码块（`FlowPage`、`FlowGlance`），由应用层加载后传给统筹安排和总览，其他页面的代码块不含它们；前台回放 60 秒主线程超过 50 毫秒的长任务为 0；同屏包不超过 12；只在页面打开时订阅，离开即断开。读数见下“核对”。

## 对象链接

没有页面的对象写明位置，不用泛化链接顶替：

| 事件 | “打开”给什么 | 详情里还写什么 |
| --- | --- | --- |
| 交付（`task.delivered`、对象是交付） | “打开交付”：该任务页的“交付与使用”页签，并定位到这次交付（`?tab=delivery&delivery=ID`，页签滚到该交付并标记）；事件带 Session 时另有“打开 Session” | “交付记录在该任务的“交付与使用”页签，打开后定位到这次交付。”事件没带任务时没有链接，写“……这条事件没有带任务，无法直达。” |
| 消息（`message.*`、对象是消息） | “打开该 Session 的对话”（工作台没有单条消息页面） | “这条消息在该 Session 对话中查看，没有单条消息页面。”事件没带 Session 时没有链接，另写“读不到是哪个对话” |
| 其他带任务的事件 | “打开任务”（任务页第一个页签）；带 Session 另有“打开 Session” | 无 |
| 不带对象的事件（通知等） | 无 | “这类对象没有单独的页面” |
| PR（交付、验收的安排／观察／复核／关闭、任务完成类事件） | 无：调度事件流不含 PR | 单列一行“PR：读不到：调度事件流不含 PR”，不静默省略，也不去猜 |

## 节点打开什么

| 节点（画布与 390 窄屏泳道都有） | “打开”给什么 | 打不开时写什么 |
| --- | --- | --- |
| 每个 Session 卡片 | “打开 Session”；有正在做的任务就加“打开正在做的任务”，队伍里前 3 项各一个“打开队伍里的任务” | 正在做的是消息或即时输入（没有任务）：“读不到：正在做的是一条消息……”；没有正在做的事：“现在没有正在做的事”；快照里没有这个 Session：“读不到：调度板快照里没有这个 Session……” |
| Leader | 页面拿到 Leader 的 Session 编号时：“打开 Leader 的 Session” | “读不到：页面没有拿到 Leader 的 Session 编号……” |
| 定时代班 | “打开日程” | 说明它是“日程到点”这一类来源，不对应单个日程 |
| 需求 Session | “打开智能体目录” | “读不到：事件流只给身份字符串，没有给出需求 Session 的编号……” |
| 使用者、结果通知、其他身份、通知包托盘 | 无 | 各写“读不到：……”和原因（人只有身份字符串；通知是一类事件不是对象；外部身份未识别；快照只给开放包的数量不含清单） |
| 对象轨道各格（待派发、队伍、运行中、待验收） | “打开任务列表” | 数量取自快照 |
| 已验收 | “打开任务列表”；**格子自身标“近 N 小时”**（画布与窄屏都有，夹具写“窗口内”） | 快照不含已关闭任务的清单，数是窗口内的关闭事件数 |
| 已合并、已发布 | 无 | “读不到：调度事件流今天不含合并与发布……” |

夹具来源的节点只写“夹具节点没有真实对象”，不编造链接。选中节点会显示详情，不只是高亮。

## 事件到画面

| 数据 | 画面 |
| --- | --- |
| `notice.created / packed` | 结果通知 → 托盘 |
| `notice.sent / delivered / seen` | 托盘 → Leader；`next` 为 `steer` 写“送入当前一轮” |
| `task.queued / turn / run_*` | Leader → Session；轨道上相应的数量变化 |
| `task.delivered`、`acceptance.*` | Session → 结果通知；`blocked` 标红 |
| `message.*` | 发送者 → Leader 或 Session；`inserted` 与 `queued` 用不同符号 |
| `task.created / started / done / cancelled / todo / resumed / removed` | 任务本身的状态变化：画在 Leader 与所指 Session 之间；不认识的新种类写“未知事件”和它的名字 |

## 核对（自建实例）

手工脚本 tests/manual/flow-real-instance.ts 起一次性 PostgreSQL、真实协调服务（调度板路由用真实读取和 hub，网页根是构建好的工作台）和真实浏览器，用真实命令造流程，再逐项读回页面与事件表比对。它要 PostgreSQL 和浏览器同时在，CI 的浏览器作业没有 PostgreSQL，所以不在 CI 里。

```
/tmp/nt/pgrun.sh 'EVOLOOP_BROWSER_TEST_PLAYWRIGHT_MODULE=… EVOLOOP_FLOW_SCREENSHOT_DIR=<私有目录> node --import tsx tests/manual/flow-real-instance.ts'
```

| 造的流程 | 逐项核对 |
| --- | --- |
| 8 个任务经 Session 队伍、确认、Run；3 个经人类使用与关闭；一次提供方额度暂停 | 事件列表条数和序号 = 事件表；对象轨道 = 快照，已合并、已发布写“读不到”；受阻 Session 卡写“受阻”；卡住的地方数 = 快照 |
| 点事件、点包 | 详情给出真实任务链接，打开的是该任务页；包停在目标旁、指针点得到 |
| 实时派发；断线期间派发；断线 2.5 秒后恢复 | 3 秒内出现；提示续传位置；列表 = 事件表，序号无重复；重连次数写在画面上 |
| 末尾点“从头回放”；60 秒前台回放 | 游标回到起点并向前走；长任务 0；同屏包不超过 12 |
| 离开动态页；总览；1440 与 390、浅色与深色；减少动态效果；键盘 | 事件流连接 1 条变 0 条；小卡片有卡住的地方、最近事件和链接；无页面级横向滚动；没有流动动画；Tab 走完所有节点和前 30 行 |
| 在别的页面打开 | 不加载动态页的代码块 |

自建实例没有原生运行时，真实交付要经 Run 的签名提交，所以交付行直接写入（数据库触发器照常产生 task.delivered），已关闭的 3 个任务的交付不带来源 Run。
