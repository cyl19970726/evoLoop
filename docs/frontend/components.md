# 组件清单：用哪个、何时用

工作台只用一套组件。新页面先在这里找，找不到再新增，并把新组件补进本表。

**目标与现状。** 目标是基础组件放在 `packages/ui`（`@evoloop/ui`），基于 shadcn/ui 和 Radix，样式只引用[设计基础](foundations.md)的 token（[DEC-036](../decisions.md#用户已确定的方向)）。这个包不依赖业务合同、不发请求，文案由调用方传入。现状：`@evoloop/ui` 已有下表的基础组件和状态组件，以及头像与 Logo，样例页在工作台的 `/ui`；对话流组件也已实现（样例页“对话流与输入框”一节可以实际输入 `/` 和 `@`），对象速览还没有实现。工作台已没有旧组件（本地的 shadcn `Button`、`Sheet` 和旧的 `Alert` 在 #229 PR10 删除），基础样式对整页生效，见[前端架构](architecture.md)。迁移由[前端改版 issue #229](https://github.com/cyl19970726/evoLoop/issues/229) 跟踪。上游组件的来源与许可登记在 `apps/workbench/THIRD_PARTY.md`。工作台源码里不写原生的 `<button>`、`<select>`、复选框、单选和 `confirm()`，由 `apps/workbench/test/style-budget.test.ts` 检查；留下的几个按钮在登录门和首屏的错误页里（首屏不带组件库），写在该测试的例外表里，各带理由。

## 基础组件

| 组件 | 用途 | 规则 |
| --- | --- | --- |
| Button | 触发操作 | 胶囊形。变体：`primary`（墨色，每屏最多一个）、`secondary`（默认）、`ghost`（列表与工具栏）、`danger`（不可逆操作）；尺寸 `default`、`compact`。文字以动词开头，2–6 个字。另有三种不是胶囊的变体，默认尺寸 `inline`（不带高度、内边距和字号）：`link` 是写在文字里的操作（“重试”“在右栏查看”），墨蓝字、悬停下划线；`row` 是点了会改变页面所显示内容的行或卡片（阶段、循环、目录项），用 `aria-pressed` 标出选中项；`tab` 是页签条里的一项，用 `aria-selected` |
| IconButton | 只有图标的操作 | `label` 必填，用作可读名称和悬停提示 |
| Field、Input、Textarea、Select | 表单输入 | 标签在上，说明和错误在下，三者都和输入框关联；错误写原因和改法。Select 是原生下拉，外观同 Input；`compact` 用于工具栏和左栏的筛选 |
| Checkbox、RadioGroup | 多选、单选 | 基于 Radix。放进 `<label>` 和文字写在一起，点文字也能勾选；空格切换，单选组用方向键移动并选中；在表单里仍随表单提交值 |
| StatusTag | 显示状态 | 只按[状态表](foundations.md#状态的视觉表达)渲染，颜色加图标加文字 |
| Badge、CountDot | 计数、类型、短标记 | Badge 只用中性色，不表达状态；CountDot 是“待我处理”等入口上的陶土色计数，0 时不显示；数目核对不了时（`count={null}`）显示灰色问号，读作“数目待核对”，不显示可能错的数字 |
| Notice | 页内提示 | 信息、等待、失败三种；不代替空状态 |
| Dialog、ConfirmDialog | 确认危险或低频操作 | 写清影响对象和确认后的结果；不放长表单。会丢东西的一问一答（清空草稿、离开项目）用 ConfirmDialog：焦点先落在取消上，Esc 和点空白处都算取消。首屏还没有组件库时（`App.tsx` 里离开项目、退出）用 `shared/confirm.ts` 的 `askConfirm()`，由登录后加载的 `ConfirmHost` 显示同一个弹窗，浏览器前进后退也等它的答复。不用浏览器的 `confirm()` |
| Sheet | 窄屏导航、窄屏右栏 | 从边缘滑出，Escape 关闭并回到触发位置 |
| DropdownMenu、Tooltip | 次要操作、补充说明 | 不把主要操作藏进菜单 |
| Tabs | 同一对象的平级视图 | 少用；优先一条连续的内容流 |
| Table | 表格视图、版本差异 | 原生表格语义，表格内部横向滚动，行点击不吞掉单元格里的链接 |
| ListRow | 左栏和列表里的一行 | 用细线分隔，不做成一张张卡片 |
| CollapsibleRow | 一行摘要，点开看详情 | 收起时一行灰字，展开后缩进显示 |
| AgentAvatar、AgentMark、PersonAvatar | 智能体头像、智能体自选的标识、人的账号 | 按职责取底色、按实例取发型与配饰，规则见[设计基础](foundations.md#智能体头像)；人的账号用陶土底首字母 |
| Logo | 产品标志 | 只用 `packages/ui/src/` 里的三个 SVG，规则见[设计基础](foundations.md#logo) |

## 状态组件

| 组件 | 什么时候出现 | 必须包含 |
| --- | --- | --- |
| EmptyState | 确认没有对象 | 为什么空、可以做什么；不用“暂无数据”一句带过 |
| LoadingState、RefreshingIndicator | 首次读取 / 再次读取 | 首次用骨架占位；再次读取时保留旧内容，只在旁边显示 RefreshingIndicator（“正在核对”） |
| ErrorState | 读取或操作失败 | 发生了什么、旧内容是否仍在、下一步；技术细节可展开 |
| UnknownState | 结果未知、权限不足、机器离线 | 已知的最后事实、原因、谁能处理、怎样查回 |

## 对话流组件

Session 页中间栏用这一组组件，任务和文档的进展时间线也复用它们。

| 组件 | 用途 |
| --- | --- |
| MessageBubble、Mention | 人的输入，深色气泡（`user-bubble`），靠右，下方可加一行回执（如“已转给架构 · 已送达”）；提到的智能体用 Mention 显示成行内标记 |
| AgentMessage | Agent 的回复，无气泡正文，支持 Markdown |
| ToolSummary | 工具调用折叠成一行灰字，例如“执行了 5 个指令、读了 3 个文件，1 次失败 ›”，展开后每步一行，失败标红；收起时失败的和正在进行的一步仍留在行下 |
| NestedActivity | 子 Agent 或子任务的内容，缩进显示在摘要下面 |
| LiveStatusLine | 正在进行的事，一行，带耗时 |
| QuestionCard | 需要人回答的问题，嵌在流里，写明谁能回答、何时有效 |
| TodoList | Agent 的待办清单，固定在输入框上方；每步显示已完成、进行中、待做，全部完成后折叠成一行 |
| QueuedMessages | 已排队、还没送进当前一轮的消息，可逐条取消 |
| TurnSummary | 一轮结束时的一行小结：产出、交付、下一步等谁 |
| Composer | 底部胶囊输入框，固定在中间栏底部；Enter 发送，运行中按运行时能力补充到当前一轮或排到下一轮，Cmd/Ctrl+Enter 排到下一轮，带停止按钮；可附带任务或文档引用；下方一行显示模型、上下文用量与排队数。输入 `/` 打开 CommandMenu，输入 `@` 打开 MentionMenu |
| CommandMenu（Composer 内） | 只在输入框开头输入 `/` 时弹出，`/` 后出现空格就关闭；在中间输入的 `/` 是普通文字。内容：上半是当前职责可用的技能（中文名、一句说明、右侧小字技能名），下半是命令（停止这一轮、撤回排队消息、关联任务或文档）；方向键选择，回车确认，Esc 关闭 |
| MentionMenu（Composer 内） | 在开头或空格后输入 `@` 时弹出（`mail@example` 里的 `@` 不算）。内容：其他智能体（头像、状态、空闲时“立即送达”、忙时“排队”）和统筹；选中后这条消息另发一份给对方，两边时间线各留一条记录；可以 @ 多个 |

## 对象速览

在右栏查看另一个对象时使用，规则见[场景与交互](scenarios.md#对象之间怎样互相查看)。速览与对象页面共用同一套内部组件。

| 组件 | 显示什么 |
| --- | --- |
| HoverCard | 悬停在对象链接上的小卡片：名称、类型、状态、版本、责任 |
| DocumentPeek | 文档阅读器（指定修订），顶部写所看版本与当前版的关系 |
| TaskPeek | 任务名称、状态与对账阶段、承接 Session、完成条件、最新交付与使用、与来源对象的关系 |
| SessionPeek | 实体卡、实时状态行、待办清单、最近几条对话、“进入对话” |
| DeliveryPeek | 交付物固定修订、技术检查与使用观察 |

## 布局组件

AppShell、Sidebar、ThreeColumn、RightPanel、PageHeader 组成页面骨架，规则见[布局](layout.md)。

RightPanel 是可组合的上下文面板：由若干“面板块”（实体卡、状态、关联对象、版本、来源、冲突与风险等）按对象类型组合成默认视图，并能以页签叠放在右栏打开的其他对象（文档阅读器、任务摘要、交付物预览、Session 摘要）。面板块和对象视图都是独立组件，新页面只需声明自己的默认组合。

## 提交表单

工作台只有一份提交表单的实现，在 `apps/workbench/src/shared/command/`。新表单只用它，不另写提交、回执或基线的逻辑。

| 部件 | 用途 |
| --- | --- |
| `useCommand` | 一条命令的提交：回执、操作 ID、基线、冲突、结果未知与核对 |
| `CommandForm` | 字段列表表单：文字、多行、下拉、多选、日期时间、单选，可折叠“高级选项” |
| `CommandFrame` | 字段排布特殊的表单（分工讨论、绑定智能体）用的外框：提示、按钮与核对 |
| `ActionForm` | `shared/ActionForm.tsx`，旧的字段列表接口（`fields`、`title`、`review`、`draftScope`），内部就是 `CommandForm` |

以下规则是默认行为，表单不需要自己实现：

1. **先存回执再发送。** 发送前先保存恢复回执和恢复意图，存不下就不发送。
2. **每次提交新的操作 ID。** 回包丢失只按原 ID 核对或重试（结果未知的操作），不换新 ID 重发。
3. **结果未知时挡住写入。** 回执保留，本项目其他写入暂停，这张表单也不能再提交；回执核清后，表单按原 ID 读回：已应用就做表单登记的收尾（`onApplied`：清空字段、收起、跳转）并清掉草稿，被拒绝就保留草稿。收尾要登记在 `useCommand` 的选项里，不能只靠 `submit` 的返回值，否则读回为已应用时不会执行。
4. **基线覆盖所有固定输入。** 表单打开时记下命令依赖的版本、修订和所选对象（`baseline`），发出的版本号只取这份记录；基线变了就不提交。
5. **没改动的表单跟随最新内容，有改动的一律提示。** 提示写明变了哪些部分和字段。只有本人改过的字段可以一键“保留我的修改”；本人和别人都改过的字段不能一键保留，要逐项选“用最新内容”或“用我的版本”，免得把按旧版写的文字按新版本发出去。“按最新内容重填”会丢掉输入，要再确认一次，旁边可以先复制草稿。
6. **冲突先重读。** 服务端答复版本已变时，表单先重新读取，读回之前只等待，不让人对着旧内容选择。
7. **草稿连同基线保存。** 传入草稿存储时，草稿和写下它时的基线一起留在页面内存里，key 带对象 ID；登出、换身份或换项目时清空。
8. **显示诊断信息。** 失败用中文说明，服务端原文放在可展开的“诊断信息”里。
9. **长度按合同核对，不截断。** 字段默认不限长度；合同有上限的字段写 `maxLength`，提交前超出就逐项提示字数，不用浏览器的 `maxlength`（它会悄悄截断粘贴的文字）。

字段排布特殊、或要写到专门接口的写入（新建任务整页、过程文档上传、Git 与外部来源登记）用 `useCommand` 加 `CommandFrame`，接口和字段通过 `send`、`validate` 选项保持原样。没有用 `CommandForm` 的多行字段，按同一条规则用 `overLimitText` 核对长度。

规则的单测在 `use-command.test.ts` 和 `action-form.test.ts`。

## 业务共享组件

这些组件理解业务对象，放在工作台的共享层，不放进 `packages/ui`：

- **ObjectLink**：链接到任务、文档、Session 等对象，显示名称，不显示原始 ID。
- **RevisionTag**：显示所看修订与当前修订的关系，例如“当前版”“旧版 · 有新版”。
- **ShortId**：需要时显示缩短的标识，悬停看完整值，可复制。
- **业务状态映射**：把 Task、Run、Delivery 等的状态转换成 StatusTag 的输入。

## 组件样例页

工作台的 `/ui` 是组件样例页（`apps/workbench/src/app/ui-samples/`），用 `apps/workbench/src/shared/fixtures/` 的假数据渲染已实现组件的各种状态，可切换浅色与深色，不需要登录。它和代码同步更新，是查看组件外观的唯一参照，文档里不放组件截图。
