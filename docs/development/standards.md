# 开发规范：从已观察问题形成可验证约束

状态：2026-10-21 按本机试用及开发流程审阅修订。当前能力和已验范围以[阶段路线](../roadmap.md#当前基线)为准；生产运行、飞书真实租户等仍须各自验证。本文维护执行与验证规则；产品和数据定义分别以[产品定义](../product/definition.md)、[架构总览](../architecture/overview.md)、[项目数据](../architecture/project-data.md)为准，不在这里重写字段合同。

**适用方式：**“必须”约束当前授权工作或被触发的实现路径；“建议”允许依据本次成本调整；“待验证”是未来验收方法，不代表该能力已运行。按[贡献入口](../../CONTRIBUTING.md#按任务选择入口)只加载相关章节。新增规则须有触发、动作、验证与依据；没有项目观察或已确认目标支撑的做法保留为建议，不把所有风险升级为审批。

## 按变更选择检查

| 触发 | 本次必须做什么 | 验证与边界 | 依据及回看条件 |
| --- | --- | --- | --- |
| 正文、导航、研究报告或发布资产变化 | 按[文档检查与构建](documentation.md#文档检查与构建)运行现有检查，核对改动页及引用。纯文字修正无需新增业务测试。 | 文档工具测试检验构建器，不证明产品运行。图、布局、原型交互改变时补相应浏览器检查。 | 当前[文档工具链](documentation.md#站点源与生成物)与既有报告实践；构建策略或发布方式改变时重看。 |
| 脚本、原型或未来业务行为变化 | 选择能捕获失败模式的最小回归检查；可行时先复现，再保留修复后的证据。 | 检查实际状态和下一次读取，不只看返回码；涉及 UI 的目标还须从普通入口操作。无需为每次小改运行所有组件验收。 | [首轮实验](../references/validation-summary.md)显示写成功、页面存在或任务答对仍可能遗漏约束；出现回归时补相应路径。 |
| 阶段交付或入口/协作行为发生实质改变 | 用无构建上下文的人或 Agent 从普通入口完成代表性任务，记录漏项与产物；产品效果另收实际用户使用反馈。 | 建议先做有限 walkthrough。它能验证规则可发现性，不能证明长期收益或用户满意。 | 首轮独立消费有约束遗漏、尚无效率优势；新用户、入口或阶段变化时重看。 |

检查通过后不重复扩大验证，除非新增修改、失败或未解决风险给出理由。未来组件的故障用例见下文，只有实现或接入该组件时才适用。

业务代码改动以 `npm run build`、`npm run typecheck`、受影响的单元测试为基础；涉及持久化或核心写入时，对专用 PostgreSQL 18 数据库运行 `npm run test:integration`。提交前的完整本机命令见[本机运行](local-run.md)，CI 实际执行范围以对应提交的工作流结果为准。状态迁移、未知恢复、外部适配和 UI 另按下文触发相应验收；不能用内存替身覆盖真实数据库验收。S1a 的当时范围和结果保留在[首片实测](../research/design-review-20261020.md)，不作为后来切片的当前验收结论。

## 证据与交付

报告必须区分以下证据，写明版本/基线、路径或样本与实际范围；没有证据就标为未知或未验证。

| 证据 | 能说明什么 | 不能据此声称什么 |
| --- | --- | --- |
| 设计或拟议验收方法 | 预期合同、实现选择和要验证的问题 | 服务存在、技术已采纳或测试通过 |
| 固定版本源码/类型核查 | 特定代码路径及请求结构 | 路径已运行、模型执行或跨端互通 |
| 自动检查、隔离实验或浏览器操作 | 实际运行路径及观察结果，分别标注真实/替身/合成状态 | 未覆盖路径、生产可靠性、用户体验收益 |
| 无构建上下文的消费与用户亲用 | 指定任务能否完成；用户实际反馈 | 小样本的长期或普遍增益 |

该区分来自[Wiki 实验摘要](../references/validation-summary.md)、[Codex 调查](../research/codex-app-server-20261019.md)与[原型审阅](../research/workbench-prototype-review.md)。固定版结果不自动转移到新版或另一语言客户端；模型、夹具或入口变更后，重跑受影响判据。

交付至少包含：**改了什么及依据、实际检查及其范围、未验证/未知结果和下一步**。涉及远程操作时另外核对：

- **PR/CI：**写清提交或 PR 身份；CI 只据对应提交的实际运行结果报告。排队、运行中和未查询保留原状态，旧提交绿灯不覆盖新差异。
- **合入/发布：**任务验收、Git 合入、文档构建和部署是独立结果。只有实际完成并核对的步骤才报完成；本地构建不证明公网已发布，也不证明分支保护存在。
- **外部写入/派发：**结果未知时保留操作 ID、目标和读入基线，先读回/对账再决定是否重试；存储接受不证明下游消费或语义正确。接入时的故障测试见对应组件表。

## 共享主分支与审阅

共享 `main` 的功能和维护变更走 topic branch → 聚焦 PR → 按风险验证 → 独立审阅 → 合入后回读。PR 围绕可独立验收的用户路径或故障边界组织；关联代码、文档和相应检查一起交付，不设行数、每包一个 PR 或每次重跑全部组件的死门槛。共享 checkout 依下节保护他人改动；从隔离工作区提交时也先核实际 base 与差异。不要直接推送、强推或删除 `main`。紧急例外须由有权者对具体变更授权，并在 PR 或任务中保留理由、影响提交、跳过的检查、补验与恢复结果；不能把例外当常规合入路径。

PR 的审阅材料简要列目标和来源、改变的用户路径、head/base commit、实际检查及范围、普通入口或外部服务的观察、未验证项。审阅者按固定 head/base 读差异、测试和必要的使用证据，给出可执行结论；作者不能仅凭自己的完成叙述充当独立审查。同一 GitHub 身份不能给自己的 PR 有效批准：在只有一个可用身份时，可由独立 Agent 或其他未参与实现者留下绑定 head 的审阅结论，平台 required approvals 暂为 0；**这项过程要求不等于平台已强制独立审查**。有独立可信审批身份或检查后再评估提高平台门槛，不为满足形式伪造批准。

合入前读回当前 PR head、base 与必要检查，核对 `app`、`docs` 工作流的实际结果及当时生效规则要求的 check 名称，确认它们对应当前 head/base 的待合入版本，且独立审阅覆盖当前差异。`pull_request` 工作流默认测试临时合并提交，检查 SHA 可不同于源分支 head；通过 GitHub PR 检查视图或对应 test merge commit 核关联，不要求二者 SHA 相等；head 改变后只复审受影响内容和检查，旧绿灯或旧审阅不自动延用。合入后读回实际 merge commit、`main` 上的检查结果与使用中的服务版本；排队、未查询、失败各按原状态报告。主分支保护的[配置模板](../assets/main-branch-protection.proposed.json)只是提案，具体 required check 名称、保护、管理员限制及例外能力必须以 GitHub 实时生效规则回读为准，不能由模板或这段规范推定平台已经拦截直推。

## 多 session 协作

并行修改或交接时，必须在当前任务/计划中写清负责文件或职责、共同接口和最终回收者；这是一份工作分配，不要求新建常设角色。开始编辑前核对基线与已有差异，交付前复核仍只包含授权范围。共享 checkout 不切分支、不回退别人修改、不把混合差异一并提交；需要提交时显式选择自己负责的文件，并核对暂存差异。

共享服务或持久实例的版本、地址、schema 与数据环境身份须和本次证据对应；不同版本并存不自动判错，但核不清被测对象时先补读回。改动运行中的共享服务须与当前维护者协调，不能用另一个工作区的构建或旧客户端页面推断该服务已升级；迁移前按真实状态决定备份与恢复演练。令牌、私有原件和会话正文不写入公开交付材料。

同一文件有重叠需求时先交接编辑权或由单一责任者整合；跨域问题给出路径、依据与建议，交给对应责任者，不默默扩展所有权。需要构建页面供他人持续阅读时协调共享 `site/` 的写入，或用忽略目录中的独立源快照构建；不得让一次构建替换另一会话正在核验的页面。

交接至少留下任务目标、基线/实际差异、产物位置、已运行验证、未知项与接手第一步。需要回收时检查接收者实际读到并采用了哪些材料；已发消息、已读、运行完成与任务验收分别核对。依据是[历史交接边界](../decisions.md)及本轮并行文档维护的文件分工；独立快照是当前减少干扰的建议，尚未量化收益。运行时、协作方式变化或出现重叠覆盖时回看，不为每次单人小修增加交接仪式。

## 从隔离实验得到的约束

以下规则用于实现或维护对应知识/交接路径，不要求普通文案修正重跑 Wiki 实验。版本和合成样本边界见[验证摘要](../references/validation-summary.md)。

| 已观察问题及依据 | 触发与必须动作 | 验证方法（接入时运行） | 何时回看 |
| --- | --- | --- | --- |
| OpenViking 0.5.0、nashsu 0.6.12 同基线覆盖可丢更新；新版本源码变化不等于修复已验证。 | 多写者更新同一知识页时，在实际服务写入边界比较读入 revision/hash；或限制串行发布并检查基线与差异。冲突保留差异，不盲重试覆盖。 | 两写者同读一版，只接受一份无冲突提交，另一份拒绝或进入审阅；注入写成后丢响应，读回后不得重复或覆盖他人更新。覆盖所有开放写入口。 | 新版本、知识后端、第二维护者或旁路写入出现时。 |
| 删除来源未自动修订知识正文。 | 来源更新、撤回或权限变化时定位依赖主张，标待复核，修订前不得当作无条件当前事实；删除不证明相反结论。 | 撤回综合页来源，核反向依赖、当前读取、过时标记与修订说明；保留合法历史和不可追状态。 | 新增来源类型、依赖索引或批量摄入后。 |
| nashsu 新页采用纠正但旧中心页仍有旧建议；OpenViking 新消费者漏掉 Markdown 许可。 | 明确纠正发生时更新权威正文、相关摘要和未执行的依赖任务；保留旧结论的被取代关系。 | 搜索旧关键词并从常用入口阅读；新上下文完成任务，核对采用的修订及重要反例。仓库修订走[文档维护](documentation.md#一次正式修订怎样完成)。 | 重复纠正、入口/检索排序或用户边界改变时。 |
| 交接历史区分发送、接收、唤醒与消费，单条通知不能证明行动。 | 实现自动交接/通知时记录任务、产物、证据修订、目标和接收状态；结果未知持续对账。 | 注入暂停、重复投递和丢回包，核去重、超时复核及后续任务实际采用；人工交接按上节保留有限证据。 | 更换运行时、自动唤醒/订阅或真实漏接后。 |

## 开始业务实现时

**仅在进入业务代码或真实集成时触发。** 先核对[技术选型](../architecture/technology-selection.md)、[包职责](../architecture/packages.md)及[决定记录](../decisions.md)，记录本次已采纳选择、固定版本与尚未决定项。DEC-028 已授权实现；S1a 采用的主应用、前端与数据库版本见技术选型和锁文件，后续适配器仍按实际需求选择。必要选择未定时先形成具体建议与影响，继续不依赖它的工作，不自行把研究提案升级为决定。

下面是按组件适用的验收方法；S1a 已执行部分 PG/API/前端检查，结果见[审阅报告](../research/design-review-20261020.md)，其他路径仍待执行。按本次切片选择，组件开放相关能力前完成对应验证；部署/恢复验收随实际部署范围执行，不要求首个本地表结构实验验证整个生产系统。

| 实现触发 | 动作与验收方法 | 依据与再次验证条件 |
| --- | --- | --- |
| PG/原生 Document/任务写入 | 锁依赖并用真实 PostgreSQL 核迁移、唯一约束、同基线改版冲突及事务回滚；任务/文档变更与 outbox 同事务，网络等待在事务外。保留任务使用的旧依据和新复核结果；上线持久状态前演练断连、备份与恢复。 | [存储](../architecture/storage.md)与[项目数据](../architecture/project-data.md)；迁移、驱动、发布方式或恢复策略变化时。 |
| Feishu 或其他 connector | 在隔离真实环境核身份/字段权限/基线、出站回读、去重与回写循环；注入丢事件、乱序、写成后丢响应及人工并发。缺条件写或可靠身份映射时限制回写；删除投影不直接删主数据。 | [项目数据](../architecture/project-data.md)；租户、字段方向、权限或远端能力变化时。 |
| Codex 运行时适配 | 固定 CLI/schema，协议留在适配包；先替身核策略，再用隔离真实任务核请求关联、服务器请求、Turn 终态/中断、断线和派发未知的对账。普通 RPC ID 不作跨重试幂等键。 | [Codex 接入](../architecture/codex-integration.md)与[研究](../research/codex-app-server-20261019.md)；升级 CLI/客户端、运行方式或恢复路径时。 |
| 日程触发与在途运行 | 可控时钟核时区、重复触发、定义修订、重叠、漏触发及暂停；隔离宿主故障测试核写成后丢回执不重复派发。分别检查停日程与停在途运行，未知操作持续对账。 | [包架构](../architecture/packages.md)和[接口合同](../architecture/contracts.md)；触发器、宿主或恢复策略变化时。 |
| 首条跨系统工作闭环 | 用同一需求串起 Document 修订、Task、Wiki 反例、成果与实际接入的投影；分别核核心接受、同步、任务验收及下一 session 采用。任务要求飞书体验时才把真实飞书使用纳入该次验收。 | [日常闭环](../product/daily-loop.md)与[知识关联](../architecture/knowledge-flow.md)；扩大接入范围或产品目标改变时。 |

**高影响状态或存储变更。** 状态收敛、持久字段迁移、不可变修订、固定依据或恢复协议改变时，在 PR 中列受影响的旧对象路径，并用真实旧模式样本和专用数据库核“迁移后能继续工作或被明确拒绝”，不只核迁移成功。按实际影响选择下列检查；[PR #16](https://github.com/cyl19970726/evoLoop/pull/16) 的 012 迁移及 [PR #17](https://github.com/cyl19970726/evoLoop/pull/17)/[PR #18](https://github.com/cyl19970726/evoLoop/pull/18) 的后续修复已发生，不把它们重列为待实现功能。

| 旧对象路径 | 对应验收与保留项 |
| --- | --- |
| 非空旧库进入新模型 | 核正文原字节/hash、旧修订、Run、sealed basis 与 operation journal；当前头及新写入满足新合同，历史不回写。 |
| 旧 Task 继续更新、依据复核或外部引用决定 | 用迁移后的当前头实际写入新修订，核旧状态、固定来源、授权和版本；拒绝须有明确原因，不静默改变旧依据。 |
| 旧固定上下文再次读取与使用 | 从正式 CLI/API 读主正文及所需 Git/Wiki 固定原件；逐项报告 complete/partial，不能以当前版或摘要代替失败的固定读取。 |
| 已回看阶段的原 Task 接续 | 保留原阶段对旧启动的拒绝；有权者在 todo、无在途/未知运行时显式决定解除或改绑 active 阶段，再以新意图启动，核旧关联、回看与拒绝日志仍在。 |
| 返工或新报告后关闭同一 Task | 核旧 failed/交付和新正文修订可回查，当前技术检查、实际使用及验收只绑定本轮交付；旧成功不自动关闭新一轮。 |

**未知操作与新决定分开。** 超时、503 或回执 pending 时，先按原 operationId 读回，保留原 actor、项目、请求正文和 expectedVersion；普通 404 或暂时读不到不是“未执行”证明。仅对正式回查给出 `OPERATION_NOT_FOUND`、且属于已支持的纯事务核心命令，才可由有权操作者显式用 `receipts retry` 按同 actor、ID、payload 和基线原样重放；同时核并发只产生一份 journal/修订/outbox，确认后不再 POST。确认拒绝后重审范围、调整阶段或重新启动是新业务意图，用新 ID 和当前版本，保留旧拒绝。Codex、Wiki、飞书等外部动作走各自回读/对账，不能借核心 PG 去重推定可重放。命令、身份围栏与恢复动作的唯一操作说明见[Agent CLI](agent-cli.md#未知结果与本地回执)；本节规定何时需要相应回归证据，不复制协议实现。

## 上游前端复用与工作台验证

**复制或移植上游代码时**，必须逐文件固定仓库、commit、导出符号、直接/传递依赖和许可证；区分原样复制、换接口与只借交互重写。实际取入才登记第三方清单及适用通知，不为尚未复制的候选生成虚假 NOTICE。依据是[前端复用研究](../research/nashsu-llm-wiki/frontend-reuse.md)，其候选清单不等于已移植成果；升级或改变分发方式时重新核对。

移植时验证 import 闭包不携带 Tauri/fs、上游全局 store、凭据或模型执行链；纯函数用相同语义夹具比较否定/断链、同名页、受限来源和格式变体。Markdown/链接/图组件验证不可信内容、固定版本深链和有限输入。上述为待执行验收，编译成功不证明权限或来源语义正确。

**原型或工作台路径改变时**，从[产品路径](../product/workbench.md)选择受影响场景，从普通入口核列表关键信息与下一步、Task 主正文/固定来源、历史或报告、主动作及返回路径；桌面和 390px 页面按受影响范围实际查看。页面无整体横溢不等于关键标签可见，正文/图内部滚动和整页滚动分别判断；涉及写入时再核 409、未知回执与草稿保留。报告分别列代码或 mock、真实 API、浏览器操作、无实现上下文的 Agent 代理和真人反馈；保留初次失败与修复复测。用户授权 Agent 代理完成的范围不额外等待真人，真人主观体验和长期效果仍单列。无 UI 路径变化不追加浏览器关卡。[原型审阅](../research/workbench-prototype-review.md)保留旧模拟覆盖和缺口，模拟按钮改文字不证明外部操作完成。
