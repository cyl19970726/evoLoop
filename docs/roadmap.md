# 阶段路线与当前状态

2026-10-19。阶段划分是当前实施建议；进入下一阶段取决于验收证据，尚无承诺日期。任务执行状态未来由飞书管理，本页只汇总能力阶段和进入条件。

## 当前基线

- 已整理产品方向、职责演进、独立认知空间和正式文档的边界。
- OpenViking 与 nashsu/llm_wiki 的隔离小样本验证已完成，发现真实缺口；[摘要](references/validation-summary.md)记录版本与范围。
- 本轮建立正式产品、架构、开发规范及文档构建脚手架。具体仓库检查以提交对应的 CI 和本地检查结果为准。
- 尚无 evoLoop 业务 harness、正式飞书任务适配或生产认知库；未接入真实项目的持续协作。
- 尚未发布项目子域名文档站、创建常设业务角色或运行定时管理任务。

## 阶段及进入条件

| 阶段 | 要交付什么 | 要弄清什么 | 结束时怎样使用与判断 |
| --- | --- | --- | --- |
| M0 正式定义与仓库 | 产品、架构、规范、决定和可重建文档站 | 新读者能否理解目标与边界，Agent 能否找到当前合同 | 干净安装并重建；按文档定位一个场景及其实现边界；记录阅读反馈 |
| M1 任务与单次交接 | 一个项目的飞书任务适配、一个运行时、稳定任务与会话关联 | 实际权限和状态更新是否足以可靠接续工作 | 完成一个文档修复任务；模拟丢通知、重复请求和结果未知后恢复 |
| M2 认识改变后续行动 | 外置 Wiki 的贡献、维护、查询、修订与来源关系 | 用户纠正/反例是否真正影响新会话，代价是否值得 | 分批加入纠正，新的 session 完成任务；与直接材料读取比较；验证并发边界和恢复 |
| M3 分工管理试行 | 按证据提出并执行一次职责调整，或有理由维持现状 | 新分工是否改善持续责任，收益是否抵消交接成本 | 在相近任务中观察遗漏、返工、切换、提醒及维护成本，决定保留/修改/撤回 |
| M4 持续使用与发布 | 受管项目试点、文档子域名、运行与备份办法 | 长期材料增长和真实使用下是否可靠、可维护 | 真实阶段使用、故障恢复、成本与反馈复盘后再扩大范围 |

M1 和知识候选补验可以做独立准备，不能因此把 M2 的业务收益视为已证实。M3 的职责定义可提前讨论，但实际收益必须经过试行。正式线上发布需有可用的运行与回退方案。

## 眼前的关键工作

1. 让负责人和新 Agent 按本轮正式文档解释产品与选择一个最小业务场景，收集理解偏差。
2. 核实飞书实际权限、任务字段和运行时派发/状态接口，冻结最小交接合同。
3. 针对 OpenViking 的新版并发、来源撤回维护、原生恢复做有边界补验；候选不满足时允许换后端。
4. 选择一段能持续积累反馈的真实小任务，建立提醒、返工与接续基线；不得用合成样例成绩替代。

这些是候选工作线，尚未建立真实飞书记录，也没有据此自动启动实施会话。后续任务按已有授权、可用资源和产品优先级推进。

## 如何更新本页

能力完成须附对应提交、运行结果和验证范围；不能只因文档写好或任务被标完成就改变状态。阶段失败可能产生新的判断或缩小范围，把原因与下一动作记录清楚即可。具体执行见[开发规范](development/standards.md)。
